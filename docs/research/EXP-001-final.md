## 1. 研究问题与结论摘要

**研究问题**：一只股票**首次涨停（首板）之后**，T+1～T+5 的价格路径、回踩行为、回踩深度、
**是否跌破首板日开盘价**，以及**在不同决策时点（T+1…T+5）**上「不破 / 破位」这个条件所对应的
后续 T+5 / T+10 / T+20 表现分别是什么。

**一句话结论（纯描述，不含策略建议）**：

在**全量**样本（数据集声明的 **23978** 个事件，本轮**全部扫描**，入池 **23712** 个）里，
截至 T+5，**始终未跌破首板日开盘价**的事件占 **65.44%**（15518 条），**曾跌破**的占 **34.56%**（8194 条）——
两者**互补到 100%**（截至口径）。这两组在 T+5 / T+10 / T+20 的**中位收盘收益差**为
**+11.17pp / +10.68pp / +9.84pp**，三个视界**方向一致、量级稳定**。

> 以上为样本内描述性统计，未进行显著性、稳健性或 OOS 检验。

**决策时点条件矩阵（新增，45 格）的核心事实**：把「截至 T+k 是否跌破首板日开盘价」当作
**决策时点条件**（只使用 rd ≤ k 的信息），并让后续窗口**严格从决策时点之后开始**（rd ∈ [k+1, h]），
则**「不破」这一侧的优势随决策时点后移而收敛、甚至在 T+3 之后反转**：

| 决策时点 | 组 | T+10 窗口可用 | T+10 中位收盘收益 | 与「破位组」之差 |
| --- | --- | --- | --- | --- |
| T+1 | 不破 | 21208 | -2.39% | **+0.78pp** |
| T+2 | 不破 | 19347 | -2.02% | **+0.29pp** |
| T+3 | 不破 | 17782 | -1.85% | **-0.40pp** |
| T+4 | 不破 | 16433 | -1.64% | **-0.93pp** |
| T+5 | 不破 | 15306 | -1.18% | **-0.61pp** |

🔴 **这不是「T+1 最好」的结论**。本报告**不做**任何择优、排序或显著性主张（§8 / §24）。
它只如实说明一件事：**「不破」的区分度强烈依赖它在哪个时点被判定** ——
在 T+1 判定时两组的后续差异最大，越往后判定，差异越被「已经跌下去的那部分」吸收掉。
这与 §10（截至 T+5 判定的差值 +11.17pp）**不矛盾**，因为两者的**分组时点与收益窗口口径不同**：
§10 的分组用了 T+1…T+5 的全部路径、收益从 T+5 起算；§24 的 T+1 组只用 T+1 一天的路径、
收益从 T+2 起算。**同名字段、不同口径** —— 这是本报告最容易被误读的地方，§24 已逐格标注窗口。

**截至 T+5 的回撤深度与后续表现**（分布，不是排序）：样本最多的两桶是
`DD_BELOW_1000BP`（dd < -10%，5613 条 / 23.67%）与 `DD_500BP`（-5% ≤ dd < -2%，5412 条 / 22.82%）；
两桶的 T+20 平均收盘收益分别为 **-10.75%** 与 **+4.48%**。差得很远 —— 但这是**事后分组**
（用未来价格分桶），不能读成「回撤 -5% 就该买」。

**必须同时读到的三条限制**（详见 §16）：
1. 全部数值是**样本内描述统计**，无参数搜索、无稳健性检验、无样本外验证 ⇒ 不能作为可交易结论。
2. 样本资格含「观察窗口行情齐备」这一**数据可得性**条件 ⇒ 存在选择偏差。
3. T+5 / T+10 / T+20 的**分母各不相同**（各自只要求所需窗口完整合法），**跨视界不可直接比大小**。

### 3.3 缺口 3978 的收口（本报告 `9ci` 版的「最重要的不体面事实」现已消失）

平台强制的两条守恒式是 `eligible + excluded = candidate` 与 `Σ excludedByReason = excluded`。
**这两条式子对「压根没进候选的事件」恒真** —— 因为它们不在 `candidate` 里。

| | `9ci`（旧） | **`9cj`（本轮）** |
| --- | --- | --- |
| 数据集声明 | 23978 | 23978 |
| 平台实际扫描 | **20000**（触顶） | **23978** |
| 候选 `candidateCount` | 20000 | **23978** |
| **未被扫描 `unscannedEventCount`** | **3978** ⚠️ | **0** ✅ |
| `droppedByScanLimit` | `true` | **`false`** |
| `eventScanPolicy` | `PLATFORM_LIMIT` | **`FULL_DATASET`** |
| 入池 / 剔除 | 19877 / 123 | **23712 / 266** |
| 项目 | 一个真实 Run | **12 轮分页**（keyset 游标，无重复、无跳洞） |

**「缺口 = 0」的判据是双侧互补的**（不是单侧「不许出现告警」）：

- 缺口 **= 0** ⇒ 页面渲染**绿色** `[data-experiment-badge="full-scan"]` 徽条（「全量扫描成立」）；
- 缺口 **> 0** ⇒ 页面渲染**黄色**告警条并带**具体条数**；
- **两侧互斥**：缺口为 0 时**不得同时**出现「样本账有缺口」告警条。

缺口为 `null` 表示数据集未声明总数 ⇒ 缺口**不可知**，**不等于** 0（单测钉死）。

### 3.4 两个上限不可混淆（本轮**没有**删安全阀）

| 上限 | 位置 | 作用对象 | 超限后的表现 |
| --- | --- | --- | --- |
| 平台**默认**扫描安全阀 `EXPERIMENT_EVENT_SCAN_LIMIT = 20000` | 平台 `datasetPort` | **扫描到的事件行** | 根本没进候选 ⇒ 只能靠 `unscannedEventCount` |
| 平台**硬上限** `EXPERIMENT_EVENT_SCAN_HARD_LIMIT = 400000` | 平台 `datasetPort` | 同上 | **任何时候都不许越过**（声明式放行也顶不破） |
| 实验参数 `maxEvents` | 本实验 `run()` | **去重后的候选事件** | 逐条登记 `MAX_EVENTS_LIMIT`，进 `excludedByReason` |

**本轮方案 = 声明式放行 + 流式分页 + 分块批量读**，而不是「把上限调大」或「把内存放宽」：

1. 实验在 `descriptor` 里**显式声明** `eventScanPolicy: "FULL_DATASET"` —— 这是**一次书面放行**，
   平台据此把该 Run 的上限从 20000 提到硬上限 400000；**默认值仍是 `PLATFORM_LIMIT`**，
   没有声明的实验行为**完全不变**。
2. 扫描走 `dataset.eventPages()`（`AsyncIterable`），每轮 `limit = 2000` + keyset 游标续读，
   **不把 23978 行一次性装进内存**。
3. 批量读用 `IN (eventId…)`，**必须分块** —— 23978 个 eventId 拼成单条 SQL 是不现实的
   （实测：`EXPERIMENT_BAR_BATCH_SIZE = 2000`，每天 12 块，§18）。

审计结论（规格 §3 要求「先审计不写代码」）：**分页机制本来就存在**（keyset cursor + pageSize），
截断的唯一原因是 `scanLimit` 这层总上限 ⇒ 因此**不需要重建任何框架**（规格 §1）。

### 4.2 逐视界独立样本账（规格 §5 要求）

| 视界 | `eligibleCount` | `validCount` | `missingCount` | `invalidCount` | 不可用 = eligible − valid | 说明 |

missingCount + invalidCount ≥ (eligibleCount − validCount)

1. `eligibleCount` **恒等于核心样本数 23712** —— 长视界不可用**不改变**样本资格。

## 6. 三个基准价（不可混用）

| 量 | 锚 | 用途 |
| --- | --- | --- |
| `firstLimitUpOpen` | 首板日**开盘价** | **破位判定**（low < open）与「对开盘价的累计回撤」 |
| `firstLimitUpClose` | 首板日**收盘价** | **回踩判定**（low < close）、回撤深度、后续收益锚、突破基准 |
| `firstLimitUpPrice` | 事件表**涨停价** | 突破研究的第二基准 |

## 7. 回踩 / 破位 / 回撤的口径（「不破」是路径条件）

- **回踩**：`low_t < firstLimitUpClose`。
- **破位**：`low_t < firstLimitUpOpen`。
- 🔴 **「不破」是路径条件**：一旦在某个观察日跌破，该样本在该日及之后的分类**固定为破位**，
  **不会**因为后来涨回来而改回不破。因此「当日破位率」与「截至破位率」是两个不同的量：
  本轮 T+5 **当日 27.29%** vs **截至 34.56%**。
- **回撤深度**两个口径：对收盘价（负数 = 回撤）、对开盘价（首板日开盘价通常低于收盘价，
  故该口径可为正）。均用**累计最低价**，不是当日最低价。

> 本报告与代码中所有 `*OnFinalDay` 一律指**当日**，所有 `*ThroughFinalDay` 一律指**截至**。

## 16. 局限与已知偏差（不藏）

1. **样本内描述统计**：无参数搜索、无稳健性检验、无 OOS ⇒ 不能作为可交易结论，也不能据此判定任何观察日优劣。
2. **数据可得性选择偏差**：样本资格要求 rd 1..5 行情齐备（**数据可得性条件，不是价格条件**）。临近数据集末端的事件会被系统性剔除。
3. ✅ **（`9ci` 的第 3 条已消除）扫描截断偏差** —— 本轮 `unscannedEventCount = 0`，结论覆盖数据集全量。
4. **未做行业 / 市值 / 板块中性化**：`boardType` 在 v1/v2 上全为 `main`，做分层只会产出伪信息。
5. **后续视界受物理视界限制**：post 视界 rd ∈ [1,20] ⇒ T+20 之后的后续表现本实验**不产出**（§12 的 `next20` 列恒空）。
6. **突破率的分母随视界变化**：跨视界的 `breakoutRate` 不可直接互相比较。
7. **不破组的回撤差异含定义成分**：「不破首板日开盘价」本身即回撤下界（§10 已标注）。
8. **T+1「入场前未破位率 100%」是空路径恒真**（§12 已标注为定义结果）。
9. **`next20` 在入场日视角恒不可用**（结构原因，非计算失败）。

实测（真实库，23978 个事件）：

| 指标 | 实测值 | 判据 |
| --- | --- | --- |
| `prefixRowCount`（rd=0 读入行） | 23978 | **= 候选事件数** ⇒ rd=0 是**一次**批量读 |
| `postRowCount`（rd 1..20 读入行） | 471816 | 上界 479560（= 23978 × 20）；实际少于上界仅说明该版本远端相对日不全 |

| `maxPostRelativeDayRead` | 20 | 20 个相对日都被读过（不是只读前 5 天） |
| **`actualQueryCount`** | **252** | = 21 个相对日 × 12 个 eventId 分块 |
| `barQueryCountPerDay` | 12 | 每块 2000 个 eventId |
| **`naiveQueryCount`**（逐事件逐日） | **503538** | 252 vs 503538 ⇒ **1 : 1998** |
| 扫描分页轮数（实验侧） | **12** | `eventPageCount`（`customPayload.candidates`） |
| 扫描分页轮数（平台累计） | **24** | `datasetFacts.eventPageCount`（见下） |

**扫描分页的两次计数不是错**：实验自己那次全量扫描是 **12 轮**；
而 `loadBars` / `feature(0)` / `observation(n)` 走 `access.events()` 时**会再触发一次完整分页**
（`eventsPromise ??=` 只保证「只做一次」，**不等于「不做」**）⇒ 平台累计 **24 = 12 × 2**。

**「查询次数 = 21 个相对日而不是 20 × N」这条硬证据**钉在单测里（利用读取层调用日志）：

```
prefixCalls.length === 1
postCalls.length === 20          // 每个观察日一次
每次调用的 ids.length === 事件数   // 单条 IN (…) 批量，不是逐事件
```

> 🔴 全量后**必须分块**：23978 个 eventId 拼一条 `IN (…)` 不可行 ⇒
> `EXPERIMENT_BAR_BATCH_SIZE = 2000` ⇒ 每天 12 块。
> 这是「全量扫描」的**真实代价**，也是它没有退化成 N×M 的原因。

> 🔴 **本轮最值得沉淀的教训**：③ ④ ⑤ ⑥ 是同一个病灶的四次现身 ——
> 「**平台强制校验通过 ≠ 账目 / 命名 / 契约 / 判据正确**」。
> - 守恒式只保证它**覆盖到**的那部分自洽，覆盖不到的（没进候选的事件）它恒真；
> - 规范里的**代码示例**可能与**同一节的映射表**矛盾，照抄就错；
> - **改完实现忘了改「谁需要知道这个行为」**（模板 / 规范 / 接入文档）时，能力对**增量**等于不存在；
> - 而**判据自身**也会错，且错了的判据**不会报错**，只会安静地给出假结论（⑦）。
>
> 四处都只能靠「把不体面的数字显式出数」「真机 E2E 实测」「对作者面契约做静态扫描」「判据也要被审」发现。

顺带修正的两处：比率类统计量的 `sampleCount` 挂的是**分子**而非**分母**（已改为分类日有路径的样本数）；
`buildObservations` 里一处 `sampleCount + droppedByMaxEvents - droppedByMaxEvents` 的**死算术**。
