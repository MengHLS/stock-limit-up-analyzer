# 首板回撤：入场对齐退出协议 V1

> 状态：**FROZEN**
>
> 协议 ID：`first-board-pullback-entry-aligned-exit-v1`
>
> 协议版本：`1.0.0`
>
> 冻结日期：2026-09-22
>
> 适用范围：首板后回撤研究的入场对齐退出曲线、路径分类和退出规则竞争。
>
> 变更规则：本文件冻结后不得原地修改规则。任何口径变化都必须建立 `V2` 并生成新的协议版本和协议指纹。

## 1. 研究问题

本协议回答三个彼此独立的问题：

1. 从**实际入场日**开始，持有 `1..10` 个交易日时，收益、风险和胜率如何变化。
2. 相同终点收益是由哪些不同路径形成的，路径类型之间是否存在稳定差异。
3. 在相同事件、相同入场和相同时间窗口上，预设退出规则相对固定持有是否产生配对增量。

本协议不回答：

- 哪个持有日收益最高；
- 哪条退出规则最优；
- 哪个首板日过滤组合最优；
- 是否已经通过 OOS。

这些问题只有在独立未读数据 Holdout 后才允许判定。

## 2. 首板日固定过滤

### 2.1 主事件池 `FB_CORE_V1`

一个事件进入主事件池，必须同时满足：

- Dataset 构建口径为沪深主板；
- Dataset 构建阶段已经排除 ST；
- `isFirstLimit = true`；
- `tradeDate` 当日行情完整且未停牌；
- `close` 严格等于交易所四舍五入后的 `limitUpPrice`，比较容差固定为 `1e-9`；
- `previousClose > 0`、`limitUpPrice > 0`；
- 事件日 OHLC 合法，不存在 high / low 倒挂或非正价格。

不满足任一条件的事件必须逐条进入剔除账，不得静默丢弃。

### 2.2 一字板处理

一字板定义为：

```text
open = high = low = close = limitUpPrice
```

上述等式的浮点比较容差固定为 `1e-9`。

主研究默认使用 `FB_CORE_EX_ONE_WORD_V1`，即从 `FB_CORE_V1` 中排除一字板。

一字板必须单独输出 `FB_ONE_WORD_V1` 旁路结果：

- 不得与主事件池合并后解释；
- 不得因为样本较少而并入主池；
- 只用于确认一字板是否具有不同路径结构。

### 2.3 首板日额外过滤

首板日额外过滤只有两个冻结层级：

| 层级 | 规则 | 用途 |
|---|---|---|
| `Q0` | 不加额外过滤 | 主口径 |
| `Q1` | 实体高度 `>0.1%` 且换手率 `<10%` | 敏感性口径 |

其中：

```text
实体高度 = (close - open) / close
```

`Q0` 和 `Q1` 必须使用完全相同的入场、路径、退出和统计口径。不得只报告表现好的层级。

换手率缺失的事件只从 `Q1` 剔除，不从 `Q0` 剔除。缺失值不得填 0。

## 3. 入场方式

只允许以下三种冻结入场：

### 3.1 `ENTRY_FIXED_T1_OPEN`

- `T+1` 开盘入场；
- 要求 `canBuyAtOpen = true`；
- 实际入场价格为 `T+1` 的 `open`；
- 决策时信息截止于首板日收盘。

### 3.2 `ENTRY_FIXED_T6_OPEN`

- `T+6` 开盘入场；
- 要求 `canBuyAtOpen = true`；
- 实际入场价格为 `T+6` 的 `open`；
- 决策时信息截止于 `T+5` 收盘。

### 3.3 `ENTRY_DYNAMIC_PULLBACK_V1`

- 观察窗口固定为 `T+1..T+5`；
- 触发条件为首次收盘满足：

```text
close <= firstBoardClose × (1 - 100bps)
```

- 触发前任意一天 `close < firstBoardOpen - 1e-9` 则永久取消本轮入场；
- 触发后的下一交易日开盘入场；
- 若触发日为 `T+5`，则入场日为 `T+6`；
- 要求 `canBuyAtOpen = true`；
- 实际入场价格为入场日 `open`；
- 决策时信息截止于触发日收盘。

三种入场方式必须分开统计。不得把不同入场方式的交易合并成一个总体均值。

## 4. 入场对齐

### 4.1 持有日定义

入场日定义为 `holdingDay = 1`。

```text
holdingDay = tradingDay - entryDay + 1
```

例如：

- `T+6` 开盘入场，`T+10` 收盘是 `holdingDay = 5`；
- `T+1` 开盘入场，`T+5` 收盘同样是 `holdingDay = 5`。

### 4.2 冻结视界

| 名称 | 持有日 | 用途 |
|---|---:|---|
| `H1..H10` | 1 至 10 | 完整退出曲线 |
| `HOLD_5` | 5 | 主视界 |
| `HOLD_10` | 10 | 辅助视界 |

`T+20` 不属于本协议的退出曲线和规则竞争主口径。

### 4.3 逐日收益曲线

对每个 `holdingDay = 1..10` 输出：

```text
netMark(d) = close(d) / entryOpen - 1 - roundTripCost
```

其中 `roundTripCost` 固定为 `20bps`。

曲线必须同时输出：

- 样本数；
- 事件交易日数；
- 均值；
- 中位数；
- 胜率；
- P5、P25、P75、P95；
- 日期聚类 Bootstrap 95% CI；
- MFE、MAE；
- 峰值日、谷值日；
- 右删失数量。

### 4.4 共同样本 `COMMON_10`

为比较不同持有日，必须同时建立 `COMMON_10`：

- 只在持有日 `1..10` 行情完整且可用的样本上计算；
- `H1..H10` 的曲线必须来自同一个事件集合；
- 非共同样本数量必须单独输出；
- 不得用不同事件集合直接比较 `H5` 和 `H10`。

## 5. 路径指标

路径指标以实际入场开盘价为锚：

```text
MFE = max(high(d) / entryOpen - 1), d = 1..10
MAE = min(low(d) / entryOpen - 1), d = 1..10
ExitReturn = close(10) / entryOpen - 1
PeakDay = argmax(high(d) / entryOpen)
TroughDay = argmin(low(d) / entryOpen)
```

路径指标使用毛价格：

- 用于分类，不扣成本；
- 组合或规则的最终收益必须扣 `20bps`；
- 不得把盘中 high / low 当作可成交价格。

## 6. 路径分类

### 6.1 分类阈值

路径分类固定使用 `±2%`：

- 有利阈值：`MFE >= +2%`；
- 不利阈值：`MAE <= -2%`；
- 终点：`ExitReturn > 0` 或 `ExitReturn <= 0`。

所有阈值比较的浮点容差固定为 `1e-9`。

### 6.2 分类优先级

按以下顺序逐条判定，首个满足的分类即为最终分类：

1. `UP_SMOOTH`

```text
ExitReturn > 0
MFE >= +2%
MAE > -2%
```

2. `UP_RECOVERY`

```text
ExitReturn > 0
MFE >= +2%
MAE <= -2%
```

3. `WEAK_RECOVERY`

```text
ExitReturn > 0
MFE < +2%
MAE <= -2%
```

4. `FADE`

```text
ExitReturn <= 0
MFE >= +2%
```

5. `WEAK`

```text
ExitReturn <= 0
MFE < +2%
MAE <= -2%
```

6. `FLAT`

```text
上述五类均不满足
```

### 6.3 路径资格

一个交易进入路径分类，必须满足：

- 入场可买；
- `holdingDay 1..10` 行情完整；
- 每个标记日未停牌；
- 第 `holdingDay = 10` 日 `canSellAtClose = true`。

不满足路径资格的交易进入 `PATH_INELIGIBLE`，不得伪造路径分类。

## 7. 退出规则竞争

### 7.1 规则集合

退出规则固定为以下集合，不得在同一 Run 内新增阈值或临时规则：

| 规则码 | 规则 |
|---|---|
| `HOLD_5` | 持有到 `holdingDay=5` 收盘 |
| `HOLD_10` | 持有到 `holdingDay=10` 收盘 |
| `STOP_BELOW_EVENT_OPEN` | 收盘跌破首板开盘价，下一可卖开盘退出，否则 `HOLD_5` |
| `STOP_BELOW_LIMIT_UP` | 收盘跌破首板涨停价，下一可卖开盘退出，否则 `HOLD_5` |
| `TP2` | 首次收盘 `>= +2%`，下一可卖开盘退出，否则 `HOLD_5` |
| `SL2` | 首次收盘 `<= -2%`，下一可卖开盘退出，否则 `HOLD_5` |
| `TP2_SL2` | 首次收盘触及 `+2%` 或 `-2%`，下一可卖开盘退出，否则 `HOLD_5` |
| `TP5` | 首次收盘 `>= +5%`，下一可卖开盘退出，否则 `HOLD_5` |
| `SL5` | 首次收盘 `<= -5%`，下一可卖开盘退出，否则 `HOLD_5` |
| `TP5_SL5` | 首次收盘触及 `+5%` 或 `-5%`，下一可卖开盘退出，否则 `HOLD_5` |

### 7.2 执行口径

- 信号只在收盘后确认；
- 执行价格为下一可卖开盘；
- 如果下一开盘跌停或不可卖，继续向后寻找可卖开盘；
- 若在 `holdingDay=5` 收盘前没有可卖点，回退到 `HOLD_5` 收盘；
- 所有规则都在相同的事件 × 入场 × 时间窗口上配对比较；
- 基准固定为 `HOLD_5`；
- 主结果输出“规则减 `HOLD_5`”的配对均值、中位数和 Bootstrap CI。

### 7.3 不在本协议内的规则

以下规则不进入 V1 主竞争：

- 成交量未恢复退出；
- 移动止损；
- 时间止盈；
- 基于 MFE 回吐比例的退出；
- 任何使用参数搜索产生的阈值。

这些规则只能在另一个独立协议中测试。

## 8. 统计口径

- 往返成本固定 `20bps`；
- Bootstrap 固定 `1000` 次；
- 日期聚类 block 固定 `20` 个交易日；
- 固定随机种子 `20260922`；
- 所有分组统计必须带事件交易日数；
- 样本数少于 `100` 或事件交易日少于 `50` 的格子标记为 `INSUFFICIENT_SAMPLE`，不得据此给结论；
- 所有退出规则比较必须是同事件配对差值；
- 多重规则比较不得只报告获胜规则；
- 未做独立 Holdout 前，一律标记为 `EXPLORATORY`。

## 9. 输出产物

实现实验时必须至少输出：

1. `entry_alignment_curve`
   - `entryMode × holdingDay`；
   - 全样本和 `COMMON_10`；
2. `path_class_summary`
   - `entryMode × pathClass × Q0/Q1`；
3. `exit_rule_competition`
   - `entryMode × rule × Q0/Q1`；
   - 相对 `HOLD_5` 的配对差值；
4. `sample_accounting`
   - 事件池、过滤、入场不可买、路径不完整、退出不可卖的逐层数量；
5. `protocol_manifest`
   - 协议 ID、版本、规则码、参数和代码 digest。

## 10. 不得做的事

- 不得从 `H1..H10` 中选择收益最高的持有日；
- 不得从规则集合中选择表现最好的规则后，把同一样本称为验证通过；
- 不得修改 `±2%`、`100bps`、`20bps` 等冻结值；
- 不得把 v2 / v3 / v4 重新称为 OOS；
- 不得把盘中 high / low 当作真实可成交价；
- 不得把成交量恢复退出混入 V1 竞争；
- 不得在无 `COMMON_10` 的情况下直接比较不同持有日；
- 不得只报告均值，必须同时报告中位数、胜率和 CI。

## 11. 后续验证边界

本协议先用于 `EXPLORATORY` Run。

若要进入正式验证，必须：

1. 先完成协议 Run 并冻结规则；
2. 使用平台 `OBSERVATION` 阶段检查样本和执行前提；
3. 仅使用严格晚于 Observation 的未读数据启动 `HOLDOUT`；
4. 使用平台生成的 `protocolFingerprint`，不得手工自报；
5. 只有 Holdout 返回 `PASS` 才允许进入策略候选。
