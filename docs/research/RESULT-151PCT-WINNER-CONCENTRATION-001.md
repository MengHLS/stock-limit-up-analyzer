## 8. 差额 37,742 已定性：`trades[].netPnl` 重复扣除卖出侧滑点

### 8.1 事实与算式

| 口径 | 值 |
|---|---:|
| Σ`grossPnL` | 278,842.59 |
| Σ`fees` + Σ`slippageAmount` | 38,792.64 + 51,212.11 = **90,004.75** |
| Σ`netPnl`（= gross − fees − slippage，1429/1429 逐笔成立 ✅） | **188,837.84** |
| 权益增量（`finalEquity` − `initialCapital`，来自 `cash + marketValue` 台账） | **151,095.83** |
| **差额** | **37,742.01** |

代码级机制（`server/backtest/portfolio.ts:288,304` + `cost.ts:49-50`）：

```
grossPnL = (baseSell - baseBuy) * q          # 两条腿都用「无滑点基准价」
slippageAmount(price, basePrice, q) = (price - basePrice) * q   # 有符号（cost.ts:50）
netPnl   = grossPnL - fees - [(pBuy-baseBuy) + (pSell-baseSell)] * q
真实现金  = (pSell - pBuy) * q - fees
⇒ netPnl - 真实现金 = -2 * (pSell - baseSell) * q
```

而 `slippedSellPriceAdjusted`（`execution.ts:39-42`）= `price * (1 - bps/10000)` ⇒ **`pSell < baseSell` 恒成立**，卖出侧滑点**结构性为负**。于是 `netPnl` 里「减去一个负数」= **把卖出侧滑点又加回来一次** ⇒ **`netPnl` 高估 = 2 × 卖出侧滑点**。

### 8.2 量级吻合（关键佐证）

| 项 | 值 |
|---|---:|
| 差额 / 2（= 隐含卖出侧滑点总额） | **18,871.00** |
| 卖出侧名义金额（逐笔 `exitPrice × qty`，closed） | 36,974,668 |
| **隐含卖出滑点** | **5.10 bp** |
| 配置滑点 `slippageBps` | **5 bp** ✅ |
| 5bp × 卖出名义额 | 18,487.33（与 18,871 差 2.1%） |
| 隐含买入侧滑点 | 19.05 bp（高于 5bp，与 `amountAdjustedSlippageBps` 按流动性分层一致） |

**⇒ 差额不是泄漏、不是资金约束、不是未平仓盯市（5 笔持仓未实现仅 −696 元），而是 `netPnl` 的符号缺陷；量级与 5bp 滑点模型吻合到 2%。**

### 10.2 根因（已定位到公式）：3F 被冻结成 **2 / 5 / 5** 档分桶 ⇒ 合成分只有 **18** 个可能取值
`score` = 三个因子「桶位分」的等权平均。公式在 `research-experiments/first-board-pullback/twelve-factor-composite-study/result.ts`（`FROZEN-BUCKET-CONTRACT-001` 的唯一落地处）：

- `bucketPositionalScoreOf`（`:414-424`）= **`(bucketIndex + 0.5) / bucketCount`**
- `orientedScoreOf`（`:427-434`）= `orientation === 1 ? score : 1 - score`
- `compositeScoreOf`（`:437-448`）= `Σ(oriented) / 3`（等权，缺一即 `null`）

三个成员的桶数（`result.ts:231-291` 冻结）：

| 因子 | 方向 | **桶数** | 桶边界 | 可能的桶位分 |
|---|---:|---:|---|---|
| `maxAmplitude`（T+1..T+5 最大振幅） | LOW | **2** | 仅 8% 一处 | 0.25 / 0.75 —— **只贡献 1 bit** |
| `meanAmplitude`（T+1..T+5 平均振幅） | LOW | **5** | 2 / 4 / 6 / 8 % | 0.1 / 0.3 / 0.5 / 0.7 / 0.9 |
| `t1VolumeRatio`（T+1 量比） | HIGH | **5** | 0.5 / 0.8 / 1.2 / 2 | 0.1 / 0.3 / 0.5 / 0.7 / 0.9 |

⇒ 合成分 = `(maxA + meanA + t1Vol) / 3`。三者的 50 种组合**塌成 18 个不同和值**（`sum ∈ {0.45+0.2k} ∪ {0.95+0.2k}`，`k=0..8`），即合成分**最多 18 档、实测只出现 11 档**。**已逐一核对：本 Run 中出现的每一个 `score` 值都落在这 18 档之内**（0.2833 / 0.35 / 0.4167 / 0.4833 / 0.5167 / 0.55 / 0.5833 / 0.6167 / 0.65 / 0.7167 / 0.7833）。

**整个策略的排序信号本质上只有 18 档，而其中一个因子只给 1 bit。**

实测质量分布：

| score | 笔数 | 占比 |
|---|---:|---:|
| 0.7167 | **656** | **45.9%** |
| 0.6500 | 325 | 22.7% |
| 0.7833（最大） | **262** | **18.3%** |
| 0.5833 | 88 | 6.2% |
| 其余 7 档合计 | 98 | 6.9% |

**3 档覆盖 86.9% 的全部成交；单是最高分就并列 262 笔。** ⇒ 「按 `score` 取 Top-3」是在巨大并列块里选人，真正决定买哪只的是次级排序键 —— 按 `firstLimitPullback3FTopN.ts:200`，那就是 **`securityId`（股票代码）**：「同值按 securityId 破平，破平只影响边界名次」。

**⇒ 这条策略的选股，很大程度上等于「通过门槛的候选里，破平键排序最靠前的前 3 只」。**

### 10.2b 破平键与候选池规模：3 个名额 vs 每天中位 **35** 个候选

**破平键是 `securityId.localeCompare`**（两处独立实现）：

- `server/research/framework/ranking.ts:87-91` —— `delta !== 0 ? delta : left.securityId.localeCompare(right.securityId)`
- `server/research/framework/selection.ts:21` —— `(left.rank - right.rank) || left.securityId.localeCompare(right.securityId)`

而事件 `securityId` 形如 **`sec_<uuid>::event:<CODE>@<date>`** ⇒ **前导是一个不透明 UUID**，`localeCompare` 的顺序**与任何经济属性无关**（稳定，但对经济含义是任意的）。

## 11. 结论

1. **151.0958% 不是一条策略的收益，是 9 笔交易的收益。** Top 3 笔 = 63.0%，Top 5 笔 = 89.0%，Top 9 笔 = **120.2%**（剔除后 −38.09%）。
2. **主体为负、且是常态不是噪声。** 中位数 −275.90，胜率 38.42%，Top10% 贡献 438.7%（系统值）⇒ 其余 90% 合计约 **−641,784 元**。
3. **绝对盈利集中在两个年份。** 2025 单年 = 全期净利 61%；剔除 Top9 后 8 年只有 3 年为正（2021/2024/2025），2026 转 −43.90%。
4. **相对提升是真的，绝对收益不是。** Runner 逐年增量为 6/8 年为正（2021 +31.79pp、2025 +47.08pp），但 2023 −6.06pp、2026 −3.27pp；这与 `RESULT-RUNNER-HOLDING-NEWHIGH3-OOS-WFA-001` 的 **CONDITIONAL** 判定同向，并给该判定补上了此前缺失的**总收益集中度**证据。
5. **基线更极端。** `1.62.1` 的 `top5SharePct` 843.67% / `top10SharePct` 1,173.34%（全期仅 +15.79%）、`maxDrawdownDurationDays` 2,699 天 ⇒ 该策略族**整体**是尾部依赖型，不是 Runner 造成的。
6. **可作为交易的形态只有一种**：承认它是「负主体 + 正右尾」的凸性下注，用能承受长期低点的小仓位表达；**不能**当作「年化 12.75% 的收益来源」配置。参照量：`maxDrawdownDurationDays` **907 天**；权益曲线显示 **2022 年 3 月的高点直到 2025 年 5 月 12 日才被超越**（≈3.2 年水下）；`maxConsecutiveLosses` 17 笔。
7. **期末状态**：`equityCurve` 末点 `cash = 5,008.83` / `marketValue = 246,087` / `openPositions = 5`；5 笔持仓成本 246,783.22 ⇒ **未实现仅 −696 元**（不是差额来源）。账户期末近乎满仓，报告收益是收盘日 5 个持仓的盯市值结果。
8. **结论对口径不敏感**（§8.4）：三种独立损益口径下逐笔中位全为负、Top9 占比 120~155%、剔除 Top9 后全转负；最保守的现金口径结论**最差**（Top10% 565%）。
9. **入场可成交，无执行幻觉**（§9）：9/9 赢家开盘均在涨停价下方（−0.06%~−3.17%），`blockLimitUpBuys: true` 已生效，成交价与 `开盘价 × (1+5bp)` 逐笔吻合。**151% 不是「买不进的一字板」撑起来的。**
10. **`trades[].netPnl` 存在符号缺陷**（§8）：高估 2× 卖出侧滑点（实测隐含 5.10bp vs 配置 5bp）。**不影响 151.0958%**（该数出自现金台账），但**影响 `profitFactor` / `concentration` / `returnPct` / 纸面 `realizedPnL`** ⇒ 全仓所有基于逐笔 `netPnl` 的历史指标都应视为**待重算**。
11. **去掉「不是原因」的之后，剩下的问题才是真问题**：151% 既不是泄漏、不是盯市、不是资金约束、不是一字板、也不是板块规则，而是**1434 次可成交的首板回踩入场里，9 次撞上 8~9 连板妖股**。中位 −281~−310、胜率 38%。
12. **选股层对右尾零识别力**（§10.1）：Spearman(`score`,`netPnl`) = **−0.075**、对 `returnPct` = **+0.0019**；分位表非单调；`>=+50%` 仅 2/9 落在最高分位（期望 0.9）；有 2 笔赢家在 1429 名里排到 **1223 / 1326**（倒数 7%）。
13. **结构性根因**（§10.2）：`score` 是 1/60 网格的粗粒度计数，**3 个取值覆盖 86.9%**，单是最高分就有 **262 笔（18.3%）并列** ⇒ Top-3 实质由 **tie-break** 决定。**这解释了此前三个无机制记录的脆弱性观测**（加宽槽位 151%→−1.5%、剔次新 −85.71pp、trend score −210pp）——不是神秘脆弱，是排序无分辨力的必然结果。
14. **机制归因：没有可命名的共同特征**（§10.4）。题材（机器人/算力/地产，全不同；**6/9 题材为 NULL**）、上市龄（235~11746 天，`<365d` 仅 1/9）、换手率（2.42% vs 对照 2.53%）、`score` 百分位（12.8~100）**全部无聚类**。**唯一聚类是时间：6/9 落在 2025–2026** ⇒ 这是 **regime 现象，不是选股现象**。
15. 🔴 **关键限定（第四轮修正后）**：**3F 分数是弱但真实的正向信号**（全池 `rho` 0.057→0.112，随持有期上升），
    **不是噪声**；但它**不识别右尾**，且对右尾**轻微反向**（rd60 无排序 `>=+100%` 命中 58 > 排序 A 的 44）。
    ⇒ 准确结论是「**这条策略的盈利来源（右尾）与它的排序依据（低振幅偏好）结构对立**」，
    而不是「分数无信息」，也不是「量化丢了信息」（连续化增量 ≤ 0.005，见 §10.1b）。
    连续分模块已实现但**不接线**；下一步应做**以右尾为目标的排序实验**（`PLAN-RESOLVING-RANK-3F-001` §11）。
