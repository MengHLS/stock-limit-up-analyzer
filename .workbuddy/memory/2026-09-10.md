- **幂等 applier** `scripts/applyDatasetRegistry.mjs`：真实 TiDB 已执行（17 语句、0 错误、6 唯一约束全在）。

### 关键 bug 修复（真实 DB 落地中暴露）
1. 手写 migration 注释块未按 `--> statement-breakpoint` 分隔，TiDB 禁 multi-statement → applier 改「剥注释 + 按分号切」。
2. `lastCursor` 原 TEXT(64KB) 被增长中的 checkpoint JSON（cumulative 涨停历史）撑爆 `ER_DATA_TOO_LONG` → 改 LONGTEXT。

### 性能优化（smoke 基线 4.6 rows/s → 171.6 rows/s，~37×）
- Phase 1 逐事件 fetchLiquidity/fetchIndustry → 批量 IN 查询。
- Phase 2 逐事件 fetchSymbolBars → 30 交易日分块 fetchBarsRange（消除 ~95% 重叠拉取）。

## STEP DATASET-002 — Dataset 全量产品化审计（READY_FOR_IMPLEMENTATION，纯审计不改代码）

产出：`docs/step-dataset-002/DATASET-002-AUDIT-FINAL.md`（A–R 节）。

### 核心结论
- 项目并存两套语义不同、互不连通的 Dataset 架构：**旧 `server/researchDataset/`（STEP 12.6 宽行 PIT panel，内容指纹 version）** 全链路活跃（router `researchDataset.*` + 前端 `DatasetBuilder.tsx` + Research 消费 `research/datasetAccess/`→`signalEngine`）；**新 `server/datasetRegistry/`（DATASET-001 事件物理表，逻辑 version）** 已完成领域+DB+构建（真实 TiDB 237,128 行）但**零 API/零前端/零 Research 消费**。
- 两个「DatasetVersion」概念互斥：旧=内容指纹 `rd-1.0.0-1-<sha>`，新=逻辑字符串 `v1/v2`（(datasetId,version) 唯一 + DRAFT→BUILDING→READY→FAILED）。
- `first_limit_pullback` 逻辑两份实现：旧 `pullback.ts`+`tDayFilter.ts`（宽行 signal 窄化）vs 新 `detection.ts`+`path.ts`（event 物理表），都复用 `boardRules`。
- 唯一事实来源方案：事件/路径/结果=新 Registry（ds_*）；PIT panel+认证 gate=旧 ResearchDataset（research_datasets）；二者是上下游而非替代。

### 迁移路线（低→高风险）
002.1 审计固化（本步）→ 002.2 契约统一（新增 datasetRegistry router）→ 002.3 前端 MVP → 002.4 Build/Quality UI → 002.5 口径收敛（tDayFilter/pullback → detection/path）+ eventAccess→Research → 002.6 旧代码清理 → 002.7 E2E 验收。
