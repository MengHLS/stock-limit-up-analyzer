# 2026-08-30 工作日志

## 本地启动项目（股票涨停分析助手）

- 项目定位：A 股涨停复盘与量化分析工具。技术栈 React 19 + Vite 7 + Tailwind 4 + tRPC 11 + Express + Drizzle ORM + MySQL（线上为 TiDB Cloud）。
- 单服务架构：dev 模式 Express 用 Vite 中间件直接服务前端，共用 3000 端口（`server/_core/index.ts`）。
- 启动阻塞点：pnpm 未装、node_modules 未装、无 .env、MySQL 连接（线上 TiDB 密码未存于仓库，用户有可直连的原始库）。

### 关键坑与修复
1. Windows 下 `dev` 脚本 `NODE_ENV=development tsx watch ...` 前缀不兼容，须用 `NODE_ENV=development pnpm exec tsx watch server/_core/index.ts`（Git Bash）。
2. `client/src/_core/hooks/useAuth.ts`：`getLoginUrl()` 被当默认参数急切求值，`.env` 缺 `VITE_OAUTH_PORTAL_URL` 时 `new URL("undefined/app-auth")` 抛 "Invalid URL"。已改为在 effect 内懒加载 `redirectPath ?? getLoginUrl()`。
3. `server/_core/context.ts`：为跳过 Manus OAuth 登录，dev 模式（`NODE_ENV === "development"`）直接注入本地管理员 `LOCAL_DEV_USER`（id=1、role=admin，对应原始数据 createdBy=1），生产走原 `authenticateRequest`。

### 环境变量（.env，仅 DATABASE_URL 必需）
DATABASE_URL、JWT_SECRET；其余（VITE_APP_ID/OAUTH_SERVER_URL/OWNER_OPEN_ID/BUILT_IN_FORGE_API_URL/KEY/TUSHARE_TOKEN）可选，仅登录/OCR/行情需要。

4. `client/index.html`：删除了 Umami 埋点脚本（`%VITE_ANALYTICS_ENDPOINT%/umami` 占位符是线上部署平台替换的，本地 Vite 不替换，浏览器报 "Malformed URI sequence"）。

## Tushare token 权限实测（低积分账号）
- `daily`：可用，频次宽松。
- `trade_cal`：可用但 1次/分钟（已改用 daily 反推日历）。
- `suspend_d`（停复牌信息）：**无权限**（code 40203，需更高积分）。
- `suspend`（每日停复牌）：有权限但 1次/分钟。
- 结论：停牌识别不宜依赖 Tushare 停复牌接口，应用「涨停日必成交 + 后续交易日缺数据」启发式判断。

## 数据质量问题：交易所后缀错误（导致「明明开盘却没同步」）
- 根因：`limit_up_records` 里部分 `stockCode` 交易所后缀写错，如 `600272.SZ`（应为 `600272.SH`）、`603269.SZ`、`003929.SH` 等。Tushare `daily` 返回的是正确后缀，同步时按错误后缀过滤 → 找不到 → 永远「未同步」。
- 规模：全库 14477 条，明确错误 29 条（22 条 `6%.SZ` 应为 `.SH`，7 条 `0/3%.SH` 应为 `.SZ`）。另有名称笔误「开发实业」→「开开实业」（08-09）。
- 正确后缀规则：6/688→.SH，0/3→.SZ，920/83/43/87/88→.BJ。
- 待办：① 写脚本纠正错误后缀；② 在 OCR 识别与手工录入加「按代码前缀自动补后缀」的规范化函数。

## 全量数据校验与修复（用东方财富/Tushare+腾讯做 name↔code 交叉核对）
- 数据源坑：Tushare `stock_basic` 限频 **1次/小时**；东方财富 `push2 clist` 会封 IP（连续拉 60 页后被封）。**可靠方案：Tushare `daily` 取全量 ts_code + 腾讯 `qt.gtimg.cn` 批量取名称（GBK，Node 用 `TextDecoder("gbk")`）**。
