## 12:24 .git 损坏恢复（.git/refs 丢失 + pack 数据丢失）

用户报「.git 文件夹被删了」。诊断：`.git` 目录仍在，但 `.git/refs/` 整个丢失（git 报 "not a git repository"）+ `objects/pack/*.pack` 3 个数据文件丢失（只剩 .idx）+ 松散对象仅 4 个。**工作区代码文件零丢失**（最新状态全在磁盘）；`logs/HEAD` reflog 完整记录了本地 20 个未推送 commit 的 hash+消息。

### 恢复方案（用户选「先备份整个项目再恢复」）
1. 全量备份：`tar` 打包到 `C:\work\sourcecode\stock-limit-up-analyzer-backup-20260909.tar.gz`（8.3M，排除 node_modules，1279 文件，含损坏 .git 的 reflog）。
2. `mv .git .git.broken`（保留 reflog 供对照）→ `git init -b main` → `remote add origin` → `fetch` → `git reset --mixed <远程hash>`（保留工作区）。
3. 结果：main 恢复到远程 origin/main `0d60b56`，本地领先的 **26 修改 + 147 新增** 文件全部变为「未提交修改」，`git status` 正常，upstream 已设 `origin/main`。

### 踩坑（重要经验）
- `git fetch origin` 返回成功、reflog 也写了，但 `refs/remotes/origin/main` ref 文件**间歇性写不进**（`update-ref` 返回 exit 0 但文件不落盘，`mkdir refs/remotes/origin` 成功后又消失）。最终手动 `mkdir -p .git/refs/remotes/origin && echo <hash> > .git/refs/remotes/origin/main` 直接写文件成功。疑似外部进程（安全软件/同步工具）间歇干扰 `.git/refs/remotes/origin` 子树，`refs/heads` 不受影响。
