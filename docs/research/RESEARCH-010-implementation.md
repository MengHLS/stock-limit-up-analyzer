## 三、29 个分析的构成（= 规格的可行部分映射）

| 组 | 类型 | 数量 | 窗 / 条件 | 目标变量（真实存在的结果变量） |
| --- | --- | ---: | --- | --- |
| **A** 回撤日 × 等频深度档 → 5 日收益 | `SEGMENT_RELATION` | 5（T+1..T+5） | 窗A = `[0,d]` 相对首板收盘涨跌幅分 5 档；窗B = `[d, d+5]` | `segment_return_{d}_{d+5}d` |
| **B** 同上 → 10 日收益 | `SEGMENT_RELATION` | 5 | 同上；窗B = `[d, d+10]` | `segment_return_{d}_{d+10}d` |
| **C** 固定百分比回撤桶 → 5 日收益 | `CONDITIONAL` | 10（T+2/T+3 × 5 桶） | 条件 = `future_return_{d}d` `BETWEEN [-0.02,0] / [-0.04,-0.02] / [-0.06,-0.04] / [-0.08,-0.06] / <= -0.08` | `segment_return_{d}_{d+5}d` |
| **D** 风险侧（最大有利偏移 / 最深跌幅） | `SEGMENT_RELATION` | 4（T+2/T+3 × 2 口径） | 窗A 同 A；窗B 口径 = `max_return` / `max_drawdown` | `segment_max_return_{d}_{d+5}d` / `segment_max_drawdown_{d}_{d+5}d` |
| **E** 回撤当日量比（缩量 vs 放量） | `CONDITIONAL` | 5（T+2 × 5 桶） | 条件 = `future_return_2d < 0` **AND** `volume_ratio_2d` 落桶（`<0.5` / `0.5~0.8` / `0.8~1.0` / `1.0~1.5` / `>1.5`） | `segment_return_2_7d` |

**口径必须说清的三件事**（否则数字会被读反）：
1. **「之后 N 日收益」的分母是 T+d 收盘价**（= 假设在回撤日收盘建仓），不是首板日收盘 —— 因为现有结果变量族的锚点是「事件日收盘 T」或「窗起点收盘 T+a」，**没有「任意买入价」这一列**。
2. **A/B/E 的分档是等频（分位数）切档，不是规格里的 0~2% / 2~4% 固定宽度**；只有 C 组是你要求的固定宽度桶。
3. **等频档位 1 = 当日相对首板收盘跌幅最深**（不是档位越大越深）。

### 4.3 现有能力**无法表达**（本次未做，需要改代码才行）

1. **「一份 Analysis」对象本身**：Feature 清单 / Target 清单 / Horizon 清单 / Descriptive 变量清单四段式配置**在 Domain Model 里不存在**。现有 `research_analysis` = `(analysisType, name, target, configJson)` 单条记录。
2. **多视界矩阵**：一次分析只能有一个目标变量；`horizons` 只有 `EVENT_STUDY` 用（且它不带分组）。要 1D/3D/5D/10D 只能 ×4 份分析。本 Run 只做到 5 日与 10 日全覆盖、3 日/1 日未建（会让分析数从 29 涨到 ~50）。
3. **二维交叉（Day × Depth）矩阵视图**：无该分析类型；也没有「两个分类维度交叉」的统计产出。
4. **`pullback_price`（绝对买入价）与 `pullback_from_limit_open_pct` / `pullback_position_in_limit_day_range`**：结果变量族全部是**比率**，没有「回撤日价格相对首板开盘价 / 相对首板日价格区间」的变量；`(P − L_T)/(H_T − L_T)` 需要跨字段比较，条件编辑器右值只能是常量。
5. **市场环境维度（market_state / regime / index_return / 涨停家数）**：`listVariables.unavailableDimensions` 明确返回 `regime` 不可用（Dataset 无该列、无 `RegimeTagProvider`）；接入后 STABILITY 才能按 regime 分组。
6. **P25 / P75 / 组内最大收益 / 组内最大回撤**：分组类分析（QUANTILE / SEGMENT_RELATION / CONDITIONAL / STABILITY）**只产出 5 个指标**（样本数/均值/中位/标准差/胜率），**不产出分位数**；分位数只有 `DESCRIPTIVE`（对单一变量）才有。所以要「组内 P25/P75」必须改引擎。
7. **一 Run 一结论的局限**：本 Run 29 个分析只生成 **1 条**自动结论，主分析按固定优先级 `QUANTILE → CONDITIONAL → EVENT_STUDY → STABILITY → SEGMENT_RELATION` 取**首个命中**⇒ 实际落到 `450011`（T+2 回撤 0~2% 那一格），**结论只反映一个格子，不能承担 5×5 矩阵的总结**（`REJECTED` 也只是这一格的判定）。
8. **Strategy Candidate 前端不存在**：`createFromConclusion` 端点已存在（RESEARCH-006.2，CODE_READY），但**网页上没有入口**，所以规格第 21 节链路最后两步「形成 Research Finding → 生成 Strategy Candidate」目前只能靠 API，不能靠页面点出来。

## 五、关键统计结果（**全部为落库数值搬运，未重算**）

> 数据源：`docs/evidence/_r007_summary.md`（由 `research_result` 逐行搬运）。全样本基线（T+2 收盘买入持有 5 日）：**n=23,604，均值 −0.53%，中位 −1.77%，胜率 41.48%**。

### 5.1 回撤日 × 等频深度档 → 之后 5 日收益（均值 / 中位 / 胜率）

| 回撤日 | 档1（最深） | 档2 | 档3 | 档4 | 档5（当日涨幅最高） | 顶档−底档 | p |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| T+1 | −1.34% / −2.24% / 39.6% | −0.32% / −0.97% / 44.0% | −0.36% / −1.27% / 43.3% | −1.49% / −2.74% / 38.0% | +1.59% / −2.53% / 43.5% | **+2.93%** | ~0 |
| T+2 | −0.92% / −1.78% / 40.9% | −0.31% / −1.04% / 43.5% | −0.59% / −1.64% / 41.3% | −0.51% / −1.73% / 41.9% | −0.35% / −3.23% / 39.8% | **+0.58%** | 0.042 |
| T+3 | −0.22% / −1.08% / 44.3% | −0.14% / −1.05% / 43.2% | −0.13% / −1.15% / 44.0% | −0.47% / −1.75% / 41.5% | −1.29% / −3.85% / 39.0% | **−1.06%** | 9.8e−5 |
| T+4 | −0.11% / −0.62% / 45.7% | +0.38% / −0.24% / 48.1% | −0.01% / −0.88% / 44.3% | −0.38% / −1.77% / 41.5% | −1.05% / −3.15% / 39.7% | **−0.94%** | 3.7e−4 |
| T+5 | −0.20% / −0.78% / 45.1% | +0.30% / −0.45% / 46.7% | +0.39% / −0.43% / 46.8% | −0.13% / −1.25% / 42.5% | −1.06% / −2.96% / 40.2% | **−0.86%** | 7.7e−4 |

**读法（三条，全部来自上表）**：
- **T+1 档5 的 +1.59% 是右偏假象**：它的中位数是 **−2.53%**（全表最差之一）、标准差 17.8%（最大）⇒ 「首板次日就大涨」那批是「少数暴涨 + 多数阴跌」，**只读均值会读反**。
- **越往后，「回撤深的」反而比「当日涨的」好**（T+3/T+4/T+5 顶底差为负，p<0.001）⇒ 「首板后越晚追高越差」。
- **顶底差全部 ≤ 3pp、胜率全档都 < 50%、中位数几乎全负** ⇒ 单靠「第几天 + 深度」两维**不足以构成正期望**；10 日口径下 T+2 的顶底差进一步降到 +0.26%（p=0.48，不显著）。

### 5.2 固定百分比回撤桶（规格要的 0~2% / 2~4% / …）→ 之后 5 日收益

| 桶 | T+2 条件组（均值 / 中位 / 胜率 / n） | T+2 差值 vs 全样本 | T+3 条件组 | T+3 差值 |
| --- | --- | ---: | --- | ---: |
| 0~2% | −0.69% / −1.54% / 41.6% / 3,155 | −0.16%（p=0.38） | −0.23% / −1.20% / 43.6% / 2,586 | +0.22%（p=0.28） |
| 2~4% | −0.17% / −0.99% / 43.8% / 2,734 | +0.37%（p=0.058） | −0.22% / −1.22% / 42.5% / 2,444 | +0.22%（p=0.26） |
| 4~6% | −0.34% / −1.11% / 43.2% / 2,078 | +0.19%（p=0.38） | −0.04% / −0.88% / 43.8% / 2,079 | +0.41%（p=0.055） |
| 6~8% | −0.58% / −1.18% / 42.9% / 1,305 | −0.05%（p=0.86） | **+0.19%** / −0.63% / **46.6%** / 1,537 | **+0.64%（p=0.011）** |
| 8%+ | **−1.63%** / −2.63% / **37.4%** / 1,956 | **−1.09%（p=6.1e−5）** | −0.47% / −1.31% / 43.1% / 3,028 | −0.02%（p=0.93） |

**读法**：**唯一显著为负的是 T+2 的 8%+ 深跌桶**（−1.09pp，p≈6e-5）；6~8% 反而是 T+3 唯一显著为正的桶（+0.64pp，p=0.011）。即「回撤越深越好/越差」**都不成立**，只有在「**T+2 就跌超 8%**」这一极端格上能稳定看到坏结果。

### 5.3 风险侧（T+2 / T+3 等频档 → 之后 5 日最大有利偏移 / 最深跌幅）

| 档位 | T+2 平均最大有利偏移 | T+2 平均最深跌幅 | T+3 平均最大有利偏移 | T+3 平均最深跌幅 |
| --- | ---: | ---: | ---: | ---: |
| 1（最深） | 7.05% | −5.11% | 7.13% | −4.51% |
| 3 | 7.48% | −4.78% | 7.44% | −4.17% |
| 5（当日涨最多） | **12.98%** | **−6.51%** | **11.49%** | **−7.16%** |

**读法**：补偿关系清晰 —— 当日涨得多的那批**上下都大**（最大冲高 13.0% 也最深回撤 −6.5%），而**已经回撤的那批波动更小、下限更好**。这与 §44.5 第 9r 条（20 日口径）方向一致：**「等回撤再买」的主要价值是「少亏」，不是「多赚」**。

### 10.2 ② `segment_return_*` 的收益起点 = **锚定日 T+a 的收盘价**（不是首板收盘、不是回撤价、不是最低价）

代码级唯一来源：`server/researchEngine/variables.ts`

```
SEGMENT_STAT_DEFINITION.return = "close(T+b) / close(T+a) − 1"
segmentValueWindow(a, b)       = [a + 1, b]      // 锚点日只提供基准价，不计入取值
windowOutcomeVariableName(stat, a, b) = `segment_${stat}_${a}_${b}d`   // a > 0
                                      ⋯ a === 0 才复用 future_return_{b}d（基准 = 事件日收盘）
```

本 Run 29 个分析 **a = d ∈ {1..5}**，所以：

- `segment_return_2_7d` = `close(T+7) / close(T+2) − 1` ⇒ **T+2 收盘建仓、持有 T+3..T+7 共 5 个交易日、T+7 收盘平仓**（不是「T+2 那天之后第 5 天」的模糊说法）。
- `segment_return_2_12d` = `close(T+12) / close(T+2) − 1` ⇒ 持有 10 个交易日。

**落库证据**（`450002` 任一行 `resultJson`）：`windowA.variable=future_return_2d`、
`windowB.variable=segment_return_2_7d`、`valueWindowA=[1,2]`、`valueWindowB=[3,7]`、
`pairCount=23604`、`excludedForMissing=374`。D 组同理：`segment_max_return_2_7d` =
`max(high[T+3..T+7]) / close(T+2) − 1`、`segment_max_drawdown_2_7d` = `min(close[T+3..T+7]) / close(T+2) − 1`
（**收盘口径**，不是盘中最低）。

**三条必须标注**：① 全部是**收盘价成交**假设 —— 系统里没有「以回撤价 / 首板开盘价买入」的口径（§4.3 第 4 条）；
② 收益基准是 `close(T+d)` ⇒「收益 > 0」= 涨过 **T+d 收盘**，与「涨过首板收盘」不是一回事；
③ 价格 **raw 未复权**（`server/researchDataset/policy.ts` `priceBasis: raw`）⇒ 5~10 日窗口内除权除息会
机械压低收益；`certify.ts` 也把「`announcementDate` 缺失 ⇒ 复权口径不完整」列为**不能作为正式研究依据**。

### 10.3 ③ Look-ahead Bias：**本次运行未发现**，但有一个「将来一定会踩」的坑

**层 1｜分析引擎：结构级干净。**
决策点 = T+d 收盘；分组量与基准价都在该收盘可观测；窗 B 取值区间 `[d+1, b]` **严格在决策日之后**；
窗 A / 窗 B 取值区间**不得重叠**（`WINDOW_OVERLAP`，`analysisConfig.ts` + `segmentRelation.ts:80-88` 双重把关）；
`FEATURE` 只能读 `event + prefix(≤T)`、`OUTCOME` 只能读 `path/outcome(>T)`，反角色用一律 `VARIABLE_ROLE_VIOLATION`；
缺失不插补（配对要求两侧同时有限），实测缺失随窗口后移单调增加（T+1 缺 310 → T+2 缺 374 → T+3 缺 414 →
T+4 缺 476 → T+5 缺 499）⇒ 尾部样本自然退出，**没有 null→0**。

**层 2｜「当天最低价」这个问题：本次 29 个分析一处都没引用 `low`。**
口径清单实测只有 `return`（close/close）、`max_return`（high/close）、`max_drawdown`（**close/close**）；
`min_return` / `lowFromEventClose` **未被任何分析使用**，`max_drawdown` 也不是盘中深跌。

数据集侧的「触及且不破」确实用 `low`（`server/researchDataset/pullback.ts#screenSingleTarget`：
`broken = 窗口内任一 low < targetPrice`），但 **390002 没有启用回踩筛选**：

- `dataset_version.filterDefinitionJson` 只有 build-config（`events=[{relativeDay:0,kind:"firstBoard"}]`、
  `preWindowDays/postWindowDays=20`、`outcomeHorizons=[5,10,20]`、`batchSize=1000`）—— **无 `pullback`**；
- `universeDefinitionJson = {"universe":"all-a-shares","source":"stock_daily_prices","boards":["main"],"excludeSt":true}`；
- 生产该版本的 `server/datasetRegistry/builder.ts` **不含** `screenFirstBoardRow` 调用
  （回踩筛选只活在 `server/researchDataset/builder.ts` 那条管线）。

⇒ **不存在**「用当日最低价当买入价」，也**不存在**「用 T+3~T+5 的低点决定 T+2 是否入选」的样本选择前视。
**代价**：样本 = **全部首板事件**（主板 / 非 ST / 2024-09-01~2026-09-01，**23,978 事件 / 2,967 只**），
**不是**规格设想的「首板后有效回撤事件」—— 这正是 10.1 里 T+2 档4/档5 全是上涨样本的原因。

🔴 **将来预警（应写进 Dataset 层规则）**：一旦给 390002 加上回踩筛选（`targetTypes` + `observationWindowDays=5`），
`broken` 是**用整个 T+1..T+5 的信息**决定入池；若再以 T+2 为决策点做分析，就是**样本选择层的 look-ahead**
（幸存者偏差：把「T+3 才跌破」的样本删掉 ⇒ 人为抬高 T+2 的胜率）。要做必须改成**按决策日滚动的窗口**
（T+1..T+d）重算入池，否则该结论不能当作 T+d 的可交易信号。

**层 3｜两点未取证 / 会影响读数（不是 look-ahead）。**
① `excludeSt` 走 universe 逐日 asOf 解析（`researchDataset/universe.ts#resolveAsOfForRequest` → 逐日 PIT），
维度本身是 PIT 的；但 390002 落库只存了**输入 JSON**（`asOfPerTradeDate` 是否开启**无法从库反查**）⇒
按纪律记为**未取证的假设**，不得当成已验证。② 「守住事件日最低价」类筛选（`holds_event_low_5d`）本次**没有**加 ——
避免了错口径（O_T 不可用），但也少了规格的一条筛选条件。
