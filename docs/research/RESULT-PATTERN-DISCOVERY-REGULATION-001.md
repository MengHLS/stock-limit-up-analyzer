## 10. 可能存在的状态切换 Pattern

本轮**没有证据支持**任何监管后状态切换 Pattern。

以下仅作为下一轮待验证假设，不是发现：

### P1：公告后重新计数窗口

```text
official announcement
→ next applicable trading day / resetDate
→ post-reset window
```

检验问题：重新计数后是否出现新的资金重新定价窗口。

### P2：监管后缩量止跌 → 重新放量突破

检验问题：先缩量止跌、后成交量恢复并突破前高的事件，是否比持续缩量或继续破位的事件更容易重新创新高。

### P3：快速回撤但不破关键位置

检验问题：监管后快速回撤但未破坏关键支撑的股票，是否更容易形成二次创新高。

### P4：持续破位 → 趋势终结

检验问题：监管后跌破关键位置并伴随成交额继续萎缩或放量下跌的股票，是否更接近趋势终结。

### P5：监管事件是阶段状态切换还是趋势终结

当前状态：**无法判断**。

需要事件后生存分析、匹配对照组和交易规则重算日期后才有资格讨论。

## 12. PIT 风险

1. 公告日期不等于公告首次公开时间。
2. 公告可能盘后发布，T 应按下一可用交易日处理。
3. 异常波动 / 严重异常波动可能在次一交易日或复牌日起重新计算。
4. 上交所、深交所规则不同，且历史规则有版本变化。
5. resetDate 不能由历史累计异动次数机械滚动推导。
6. 停牌窗口由缺失行情推断，可能把数据缺失误判为停牌。
7. 复牌日期缺失时不能用“下一根 K 线”自动补齐。
8. 事件类型和公告标题必须先于价格标签固定，禁止用未来价格反向筛选事件。
9. 匹配对照组必须使用事件时点之前可见的特征，不能用未来收益匹配。
10. 当前全市场行情完整到 2026-09-04；此后仅约 400–500 只股票有数据，不能扩展成全市场事件窗口。

- 方法：resetDate 后重新计数窗口的新高概率、涨停概率和成交额恢复
- 当前状态：不可检验

### H3：快速回撤但不破关键位置是否更容易重新创新高

- 数据要求：事件后逐日 OHLCV + 事件前关键位定义
- 方法：回撤深度 × 是否破位 × 重新创新高概率
- 当前状态：不可检验

### H4：重新放量 + 突破是否区别于继续走弱

- 数据要求：事件后成交额、换手率、价格突破标签
- 方法：状态分组后比较 T+5/T+10/T+20 路径
- 当前状态：不可检验

### H5：监管是趋势终结还是阶段状态切换

- 数据要求：事件源 + resetDate + 匹配对照组 + 足够长的 PIT 历史
- 方法：事件后生存分析、创新高概率、再次涨停概率、回撤深度
- 当前状态：不可检验

### 16.4 CNINFO 字段能力

CNINFO 返回的关键字段包括：

- `secCode`
- `secName`
- `announcementTitle`
- `announcementTime`
- `adjunctUrl`
- `announcementType`
- `columnId`
- `pageColumn`

优点：

- 公告标题和公告日期可结构化；
- 有 PDF 链接，可做二次文本抽取；
- 覆盖沪深主板；
- 无需额外授权即可访问。

限制：

- `announcementTime` 目前表现为日期级时间戳，不能证明公告是在开盘前、盘中还是盘后发布；
- 没有直接的 `eventEnd` / `resetDate`；
- 没有直接的交易所异常波动重新计算规则版本；
- `announcementType` 可能是内部编码组合，不能直接当作事件类型；
- “核查”关键词会混入普通中介核查意见；
- “监管函/关注函”可能需要交易所监管页面或公告正文二次确认。

### 16.5 PIT 处置建议

下一轮使用 CNINFO 时必须：

1. 保留公告原文、抓取时间、公告日期和 PDF URL；
2. 若无法获得精确发布时间，保守地把可用信息时点设为公告日后的下一交易日；
3. 将 `announcementDate` 与 `effectiveTradingDate` 分开；
4. 上交所、深交所分别维护异常波动/严重异常波动重新计算规则；
5. `resetDate` 由规则引擎计算，不能从公告标题中猜测；
6. 事件类型由标题关键词 + 正文规则 + 人工抽样验证共同确定，禁止仅凭未来涨幅回贴标签。
