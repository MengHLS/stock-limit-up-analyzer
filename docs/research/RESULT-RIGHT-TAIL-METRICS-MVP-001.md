## 7. A2 只读核验结论（`outcome` 多出的 564 条）

**核验方法**：只读 `SELECT`，逐项对拍 `ds_first_limit_pullback_outcome` 与 `post` 表。

| 检查 | 实测 | 结论 |
|---|---|---|
| `outcome` 总行数 / distinct eventId | 178,560 / **59,520**（每 horizon 各 59,520） | 每事件每 horizon 一行 |
| `(eventId, horizon)` 重复 | **0 组** | ✅ **无重复 event** |
| 有 `outcome(h=20)` 但**无 `post rd=60`** 的事件 | **564** | 即差异来源 |
| 这 564 条的 `post` 覆盖 | **有任意 post 行 = 0**；`rd1 = 0`；`rd20 = 0`；`rd60 = 0` | 🔴 **完全没有窗口行** |
| 其中 `prefix rd=0` 存在者 | 218 / 564 | 前缀部分写入 |
| 这 564 条的事件日范围 | **2025-09-26 ~ 2025-10-23**（2025-09: 101 · 2025-10: 463） | 与构建中断边界吻合 |
| 对照 `v8`（完整构建） | `outcome(h=20)` 事件 73,003 vs `post rd=60` 事件 70,802 ⇒ 差 **2,201** | ⚠️ **v8 也有差，但成因不同** |

### 🔴 结论

1. **564 条不是「outcome 独立生成口径与 post 窗口口径不同」造成的**：
   - 若是口径差（如 `outcome` 用「区间内最后可得收盘」延展），则 `v8` 上应出现同量级的差；`v8` 的差是 **2,201**，成因是**数据视界末端**（事件日晚于「数据末 − 60 交易日」时自然取不到 `rd=60`）—— 这是**设计内**的。
   - 而 v9 的 **564** 条集中在 **2025-09-26 ~ 2025-10-23 一个月**，且**完全没有 prefix/post 窗口行**。
2. **正确定因 = 构建中断的残留分片**：`dataset_build_job#900003` 在 `prefix` 表的 insert 上失败（`completedChunks = 58,256 / 71,934`，`lastTradeDate = 2025-09-03`）。该（批）分片的 **`outcome` 行已写入、而 `prefix`/`post`/`path` 未写入** ⇒ 留下 564 条「有 outcome、无窗口」的孤儿行。
3. **对本轮 Tail Metrics 零影响**：本轮收益**全部直接由 `post` 表计算**（入场 `rd6`、退出 `rd10..75`），从不读 `outcome`。这 564 条事件因缺 `post` 行，在池派生阶段即被 `MISSING_EVENT_DAY_BAR` 剔除（这也解释了 §4.1 中该原因码高达 10,897 —— 主体是 2025-09 之后窗口未构建的全部事件）。
4. ⇒ **登记为非阻断差异（NON_BLOCKING）**。**未删除、未修改任何 outcome 行；未重建 Dataset。**
