## 14. 结果复核与结论边界（2026-10-11）

> 复核依据：`_scratch/fbp3/attribution-{opportunities,buckets}.csv`、归因纯函数及工具实际实现；HEAD `f8b6810` + 含并发改动的工作区。本节只追加复核，不改历史 Run、CSV、策略或 Dataset。前文的条件性读数保留；与本节冲突的总体结论以本节为准。

### 14.1 「退出是主要瓶颈」仅来自已触发的 7 个机会，不能代表全池

SPEC 先要求通过买点，再检查其未来最大涨幅。因此 S1–S4 恒为空，`S7=4/7` 只回答「已经出现达标买点的极小子集，后来有没有实现 +20%」，不回答整个滚动池在哪里漏掉机会。§1.1 的「最大的一层不在没买」及 §4 的「指向退出而不是选股」均属于结论外推，标记 **BASELINE_DRIFT（结论范围超过分母）**。

D 组完整扩展桶表如下（原产物数值，未重算或修改）：

| 桶 | 数量 | 占扩展机会 1,612 条 |
|---|---:|---:|
| S1 支撑在机会日前已永久作废 | 569 | 35.30% |
| S2 从未触发，末日检查观察分不足 | 419 | 25.99% |
| S3 从未触发，末日检查其他拒绝原因 | 586 | 36.35% |
| S4 曾触发，但标签机会日没有可排序候选行 | 31 | 1.92% |
| S5 从未进 Top3 | 1 | 0.06% |
| S6 进过 Top3，但该锚点无成交 | 1 | 0.06% |
| S7 买过，但该锚点没有单笔实现 +20% | 4 | 0.25% |
| X 该锚点至少一笔实现 +20% | 1 | 0.06% |

S1–S4 合计 **1,605 / 1,612 = 99.57%**。可以据此说「现有买点覆盖很少，信号/资格层值得优先排查」；不能说这 1,605 条均可成交、可赚钱，或按此占比推断放宽哪个条件最有效。扩展标签仍是事后最高收盘，未验证实际成交、成本和持有风险，且采用 §3 的混合标签日选择规则。

### 14.2 S2/S3 是末日状态，不能当成机会日原因

`research-experiments/shared/rollingPoolLossAttribution/funnel.ts#derivePrimaryRejection` 固定在 `confirmMaxRdOf(spec)` 判定（D 为 rd19），未接收标签的 `actionable.confirmRd`。`tests/tools/rollingPoolLossAttribution.mts#buildUniverse` 对从未触发的锚点调用该函数，再将结果用于机会日归因。

因此会将机会出现后的状态混入归因。D 组 S3 的 586 条中，**121 条** `primaryRejection = support/SUPPORT_BREACHED`；这些没有落入「机会日前已破位」的 S1，却在末日被发现破位。另有 `NO_PULLBACK_YET` 422、`SUPPORT_PATH_INCOMPLETE` 18、`NO_CLOSE_BREAKOUT` 14、`TRIGGER_SHAPE_OK_BUT_NOT_TRIGGERED` 11。**S2/S3 数量作为当前分类结果可复现，其因果解释尚未成立。**

下一次归因修正应在每个实际机会确认日逐层检查，只读截至该日的数据；将机会日之后破位单独标记。S4 应区分「当天没有买点」与「当天有买点但因子缺失」，不能统称因子无法排序。该修正尚未执行，本节不更改原预注册或既有产物。

### 14.3 S7 混合了机会时点错过与卖出后的上涨

`funnel.ts#classifyOpportunity` 用该锚点所有触发日、全部交易判断 S5–X，没有要求成交匹配标签机会日。具体反例：

- `600172.SH@2024-09-30`：标签机会在 **rd12 确认 / rd13 入场**，事后最大涨幅 **62.31%**；当时已有 `MAX_POSITIONS_REACHED` 拒单记录。真实成交在 **rd17**，自该次真实入场起最大涨幅仅 **20.80%**，实现 **10.96%**。它不能被称为「实际买到了 +50% 机会却卖早」；应拆分早期容量阻断、迟买及退出三个环节。
- 其余三笔真实入场后的窗口最大涨幅确实超过 +50%，值得逐笔复盘，但当前产物没有输出峰值日期及「退出后」窗口最大涨幅。

`funnel.ts#tradeForwardRows` 计算的是从入场日起的全窗口最大收盘，未区分最高价发生在退出前还是退出后。因此可能混合「持仓中利润回吐」与「退出后继续上涨」。当前 S7 更准确的读法是 **买过但未实现 +20% 的锚点**，不应直接解释为四笔退出错误。

`217.99pp` 是不同交易的事后最高涨幅与实际收益之差相加，不是组合可增加的收益；不能代入当日权益 20% 的仓位规则估算复合回报。延长持仓还会改变槽位占用及后续成交，必须通过同一账户完整重放验证。

### 14.4 对下一步研究的建议

1. **先修正归因时点和机会—交易对应关系**：逐机会列出确认日、当日拒绝层、Top3/容量结果、实际入场及退出、最高收盘日期、退出后最大涨幅和持有期间不利波动。区分未买、迟买、持仓回吐和退出后上涨。先完成可验证的归因，再决定交易规则改动。
2. **优先审查支撑破位永久作废**：569 条已提供直接的排除画像，符合用户担心首板建仓后修复上涨会被漏掉的问题。建议另立事前协议比较「永久作废」与明确的「破位后修复、重新观察再触发」；保持 T+20、排序、当日权益仓位、退出及再入场口径一致。这里只建议研究，不授权修改或运行该策略。
3. **连续观察应与逐日硬门区别开**：N=5 是五天每天各过门，不等于综合观察五天后的路径评分。综合评分若开展应作为另一项单变量研究，不与支撑修复、退出调整同时改变。
4. **退出研究保留为独立问题**：先核对三个真实入场后有 +50% 空间的案例，再做账户级退出消融；不能从这三个事后赢家推出取消止损或扩大持仓一定改善收益。后续形成的候选规则须冻结后在未用于选择的样本检验，当前结果仍为探索性诊断。

本轮复核无业务代码、契约、数据库或执行路径变更，不产生新的收益结论，也未建立因子排序有效性的证据。

### 14.5 用户新增硬约束：观察期转为 ST 后禁止买入（2026-10-11）

**用户明确要求**：首板当天非 ST 不够；观察期间变为 ST 后，绝不能继续买入。该约束适用于后续滚动池研究及首次、二次和后续入场，不是排序因子或可调参数。

**现状缺口**：`research-experiments/first-board-pullback/rolling-pool-observation-window/result.ts#CONTRACT_GAPS` 的逐日 ST 条目明确为 `UNAVAILABLE`、未实现每日非 ST 控制；结果003 §6同样披露。`rollingPoolRightTail/projection.ts#PoolBar` 不包含逐日 ST 状态。`server/datasetRegistry/executionFacts.ts#deriveExecutionFacts` 虽接收 ST 状态计算价格限制，但 `canBuyAtOpen` 不等于「满足本研究非 ST 资格」。因此不能声称旧 Run 已满足本要求；当前也没有证据可统计受影响交易数。

后续执行必须满足：

1. **当日资格闸门**：观察日解析该历史时点可用的状态；ST / *ST 禁止进入可买候选及排序集合。保留原始观察和排除台账，状态恢复应依据当时可用事实重新判定，不能靠价格修复绕过 ST 闸门。
2. **成交前再次检查**：次日开盘、每次补试及每次再次入场前，重新核验成交时点的状态。昨日非 ST、今日 ST 的隔夜待买订单必须取消，不成交、不扣现金、不计成功入场。
3. **未知状态保守处理**：缺少可靠历史状态或覆盖不足时，不将 UNKNOWN 默认视为非 ST；拒绝该次买入并记录原因。若缺失广泛，研究应报告覆盖阻塞，不用大量未知拒单的结果冒充有效策略结论。
4. **PIT 与样本保留**：按状态生效时间及可获知时间判定。不能用今天的名称回填历史；不能因为一只股票后来成为 ST 就删除它在转 ST 前全部事件或合法交易。历史 Run 保留原样，补审计或合规对照必须使用新产物。
5. **验收**：至少覆盖「观察中转 ST 后出现买点」「昨日信号、今日 ST」「平仓后转 ST 又出现信号」「状态未知」四类；每类不得新增买入。所有实际入场均有成交时点非 ST 的历史证据，ST / *ST 实际买入数必须为 **0**；首次及再入场、R及Random账户使用同一闸门。
