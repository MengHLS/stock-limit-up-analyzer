## 1. 当前旧 Analysis 的实际研究口径（审计确认）

Run `510001`（29 个分析）的实际含义，已逐条对照代码确认：

```text
future_return_{d}d      = close(T+d) / close(T) - 1          ← 锚定首板日收盘
segment_return_{d}_{d+h}d = close(T+d+h) / close(T+d) - 1    ← 锚定决策日 T+d 收盘
segment_max_return_{a}_{b}d     = max(high[T+a+1 .. T+b]) / close(T+a) - 1
segment_max_drawdown_{a}_{b}d   = min(close[T+a+1 .. T+b]) / close(T+a) - 1
```

代码位置：`server/researchEngine/variables.ts`（`SEGMENT_NAME_RE`、`PATH_KIND_FIELD`、`AGG_KIND_FIELD`），取值区间 `segmentValueWindow(a,b) = [a+1, b]`（锚定日只当分母）。

逐条确认规格 §一 的四点：

| 确认项 | 结论 | 证据 |
|---|---|---|
| `segment_return_*` 是 T+d 收盘建仓 | ✅ 是 | 落库 `450002`：`windowB.variable=segment_return_2_7d`、`valueWindowB=[3,7]` |
| 不使用当天 low 作为买入价 | ✅ 不用 | 全部 target 分母是 `close`；`low_return_*` / `min_return_*` 零引用 |
| 不使用未来 low 作为样本筛选 | ✅ 不用 | 29 个分析的条件字段只有 `future_return_{d}d` / `volume_ratio_2d` |
| 不存在已发现的 look-ahead bias | ✅ 确认 | 见 §10 |

**这些分析全部保留，未删除、未改结果**，定位为「**首板后价格路径基线**」。

## 2. 为什么旧口径不能称为「回撤深度」

旧 A/B 组名为「T+d 回撤深度 5 档」，实际是 **`future_return_{d}d` 上的等频五分位**，实测切点（`resultJson.cutPoints`）：

| d | 4 个切点 | 档4 区间 | 档5 区间 |
|---|---|---|---|
| T+1 | −3.16% / −0.35% / +2.56% / +8.55% | (+2.56%, +8.55%] | > +8.55% |
| T+2 | −4.51% / −1.05% / +2.26% / +7.67% | (+2.26%, +7.67%] | > +7.67% |
| T+5 | −7.69% / −2.83% / +1.72% / +8.87% | (+1.72%, +8.87%] | > +8.87% |

三条致命问题：

1. **档4/档5 是「没回撤、还涨了」的样本**（T+2 合计约 40%），只有档1 是严格深回撤；
2. **切点逐日不同** ⇒ 同一列（如「档1」）在 T+1 是 ≤−3.16%、在 T+5 是 ≤−7.69%，**不可跨天比较**；
3. 名字里的「深度」暗示了「越深越好/越差」的经济含义，而等频分位**不携带该含义**。

### 已执行的校正

| analysisId | 原名 | 新名 |
|---|---|---|
| `450021` | 首板后回撤·T+2 **深度5档** → 之后5日最大有利偏移 | 首板后回撤·T+2 **相对首板收盘涨跌幅5分位** → 之后5日最大有利偏移 |
| `450022` | 首板后回撤·T+2 **深度5档** → 之后5日最深跌幅 | 首板后回撤·T+2 **相对首板收盘涨跌幅5分位** → 之后5日最深跌幅 |
| `450023` | 首板后回撤·T+3 **深度5档** → 之后5日最大有利偏移 | 首板后回撤·T+3 **相对首板收盘涨跌幅5分位** → 之后5日最大有利偏移 |
| `450024` | 首板后回撤·T+3 **深度5档** → 之后5日最深跌幅 | 首板后回撤·T+3 **相对首板收盘涨跌幅5分位** → 之后5日最深跌幅 |

（A/B 组 10 个分析原名已是「相对首板收盘涨跌幅 5 档」，无需改。）

### ⚠️ 无法按规格写入 description

规格 §二 要求「在 Analysis description 中明确：该分析以首板收盘价为基准……该分组不是有效回撤深度分组」。

- 领域模型：`drizzle/schema.ts` → `researchAnalysis`（`analysisType / name / target / configJson / status`）—— **无 description 列**；
- API：`researchEngine.updateAnalysis` 只接受 `name / target / config / status`；`config` 虽可容纳任意 JSON，但它是**执行配置**（引擎会解析），塞非执行字段会污染口径；
- **结论：做不到**。替代方案是把限定语写进 `name`（本次已如此做：名字自带「相对首板收盘涨跌幅5分位」这个自解释口径），或走 API 往 `configJson.note` 写（已验证可行，但网页上不可见、且非结构化）。
- 若要真正支持，最小扩展 = `research_analysis` 加一列 `description` + `updateAnalysis` 透传（1 列 1 字段，无业务逻辑）。

## 3. Dataset Version `390002` 为什么**不是**「有效回撤 Dataset」

实测 `dataset_version` 行：

```json
{
  "id": 390002, "version": "v2",
  "filterDefinitionJson": "{\"kind\":\"build-config\",\"builder\":\"first_limit_pullback\",\"configVersion\":1,
    \"events\":[{\"relativeDay\":0,\"kind\":\"firstBoard\"}],
    \"preWindowDays\":20,\"postWindowDays\":20,\"pathHorizon\":20,\"outcomeHorizons\":[5,10,20],\"batchSize\":1000}",
  "universeDefinitionJson": "{\"universe\":\"all-a-shares\",\"source\":\"stock_daily_prices\",\"boards\":[\"main\"],\"excludeSt\":true}"
}
```

三条硬事实：

1. **`filterDefinitionJson` 里没有 `pullback` 字段** ⇒ 未启用任何回踩 / 破位筛选；
2. 生产它的 `server/datasetRegistry/builder.ts` **不含** `screenFirstBoardRow`（回踩筛选只写在 `server/researchDataset/builder.ts`）；
3. 因此样本 = **全部首板事件**（主板、非 ST、23,978 个事件 / 2,967 只），**不是「发生有效回撤的事件」**。

**这正是旧分析里档4/档5 全是上涨样本的原因**，也是为什么不能把 `390002` 直接当作「有效回撤 Dataset」来解读。

## 4. 为什么**没有**给 Dataset 加 whole-window pullback filter

现有回踩筛选的判定在 `server/researchDataset/pullback.ts#screenSingleTarget`：

```ts
// windowBars = 整个观察窗（observationWindowDays = T+1..T+N）
for (const bar of windowBars) { if (bar.low < target) { broken = true; break; } }
// matched = windowComplete && results.some(r => r.hit)
```

`broken` / `matched` 用的是**整窗 low**。若拿它筛样本、再把决策点定在 T+2，会发生：

```text
T+3 / T+4 / T+5 的最低价
        ↓  决定
T+2 这个事件是否进入样本
        ↓
样本选择层 look-ahead（幸存者偏差，会人为抬高 T+2 的胜率）
```

**本任务遵守规格 §六 的硬要求：没有给整个 Dataset 加 whole-window filter**，`390002` 保持「全部首板事件」不变。

代价：新增的 5×5 里带的是「已回撤」条件，**不含**「未破位」资格（见 §5 与 §15 的缺口表）。

## 5. 新增 Analysis（Run `540001`）

**135 个 CONDITIONAL 分析**（`480001`~`480135`），全部 `COMPLETED`，全部通过引擎自身的 `resolveEngineAnalysisConfig` 预检（135/135，**先预检后建批，任一项不过则整批拒绝**）。

| 组 | 数量 | 含义 | 条件 | target |
|---|---|---|---|---|
| **A｜已回撤日** | 5 | T+d 收盘低于首板收盘（depth > 0） | `future_return_{d}d < 0` | `segment_return_{d}_{d+5}d` |
| **B｜5×5 固定桶** | 125 | 25 格 × 5 个指标 | 见下 | 见下 |
| **C｜T+5 + 破位资格对照** | 5 | 在 B 的 T+5 行上再加`未破首板日最低价` | `holds_event_low_5d == 1` + 桶 | `segment_return_5_10d` |

**B 组 5 个指标**（一个 CONDITIONAL 分析只能有一个目标变量，故每格 5 个分析）：

| 指标 | target |
|---|---|
| 之后 5 日收益 | `segment_return_{d}_{d+5}d` |
| 之后 1 日收益 | `segment_return_{d}_{d+1}d` |
| 之后 3 日收益 | `segment_return_{d}_{d+3}d` |
| 之后 5 日最大有利偏移 | `segment_max_return_{d}_{d+5}d` |
| 之后 5 日最深跌幅 | `segment_max_drawdown_{d}_{d+5}d` |

**桶条件（左开右闭，`depth = −future_return_{d}d`）**：

```text
桶 = (depth > lo)  AND  (depth <= hi)
   ⇔ future_return_{d}d < −lo   AND   future_return_{d}d >= −hi      （8%+ 无 hi）
```

| 桶 | 条件 |
|---|---|
| 0~2% | `future_return_{d}d < 0` AND `>= −0.02` |
| 2~4% | `< −0.02` AND `>= −0.04` |
| 4~6% | `< −0.04` AND `>= −0.06` |
| 6~8% | `< −0.06` AND `>= −0.08` |
| 8%+ | `< −0.08` |

> **🔴 这里修掉了一个真实缺陷（首版 → 修正版）**
> 首版把桶写成 `>= lo AND <= hi`（**双闭**），后果两条：① `future_return = 0`（**平盘，depth = 0，不是回撤**）被算进 0~2% 桶；② 边界值同时落进两个相邻桶。
> **实证**：首版 5 桶样本数相加 = **10,106** > 组 A「已回撤」的 **9,899**（多 207，正是平盘样本数）。
> 修正后用 `setAnalysisConditions` 重写 130 个分析的条件并整轮重跑，**T+1 的 5 桶加总 = 9,899 = 组 A**，闭环。
> 这正是规格 §十一（「0~2% 回撤」≠「上涨 2%」）与 §十七E 要防的事，已实测排除。

## 8. return definition（逐字写下，避免歧义）

```text
之后 h 日收益 = close(T+d+h) / close(T+d) − 1
```

- 实现：`segment_return_{d}_{d+h}d`；取值区间 `[d+1, d+h]`（**不含** d 本身）
- 分母 = **T+d 收盘价**（= 本研究第一阶段唯一的研究买入价）
- 「收益 > 0」= 涨过 **T+d 收盘**，不是涨过首板收盘
- 价格 **raw 未复权**（除权除息会机械压低收益；`certify.ts` 据此判「不能作为正式研究依据」）

## 9. entry price definition

```text
entry_price = close(T+d)          （d ∈ {1,2,3,4,5}）
```

**第一阶段禁止引入**：T+d 最低价、T+d 盘中假设价、回撤触及价、未来最低价。
⇒ 本研究**不模拟盘中成交**，是「T+d 收盘建仓」的收盘价假设。

## 14. Research Finding（只陈述数字，不下策略结论）

以 **T+d 收盘**为研究买入价、之后 5 个交易日的收盘价结果：

| 观察 | 数字 |
|---|---|
| 25 格中均值最高的三个 | T+5×2~4% **+0.52%**（n=2208, 胜率 48.2%）、T+4×6~8% **+0.46%**（n=1670, 胜率 49.8%）、T+4×2~4% **+0.42%**（n=2312, 胜率 47.1%） |
| 25 格中均值最低的三个 | T+1×8%+ **−4.12%**（n=865, 胜率 31.8%）、T+2×8%+ **−1.63%**（n=1956）、T+1×6~8% **−1.13%** |
| 「越晚买入」的单调性 | 行均值（5 桶平均）从 T+1 的 −1.35% 升到 T+5 的 +0.18%；**中位数始终为负**（−0.19% ~ −2.63%） |
| 深度与收益的关系 | **非单调**：T+1 行「越深越差」（−0.21%→−4.12%），但 T+3/T+4/T+5 行的 2~8% 桶反而比 0~2% 桶好 |
| 深度与风险的关系 | **单调**：最深跌幅从 T+1×8%+ 的 −8.47% 收敛到 T+5×2~4% 的 −3.47% |
| 破位约束的稀有度 | 「8%+ 且未破首板日最低价」只剩 **456 个**（占该桶 10.2%） |

**可以说**：「T+1 就深回撤（8%+）的那批样本，之后 5 日的收盘结果最差（−4.12%，胜率 31.8%），且过程中最深跌幅最大（−8.47%）」。
**不能说**：「最优买入规则 = T+5 / 2~4%」—— 这需要 Parameter Search → Backtest → Evaluation → Robustness → OOS → Walk-Forward。

**离线交叉验证（§6.6）支持的稳定性判断**：补上「未破首板日开盘价」的滚动资格后，上述特征**全部同向且量级接近**（T+4×2~4%：+0.42% → +0.38%；T+5×2~4%：+0.52% → +0.37%；T+1×8%+：−4.12% → −6.08%）⇒ **缺破位约束不会使本 Run 的方向性结论翻转**，但会**显著高估深回撤样本的出现频率**（8%+ 桶实际只剩 200 余例/日）。

## 15. 能力缺口（**这是本任务交回给你决策的核心清单**）

### ① 🔴 滚动资格判定 `valid_pullback_d = min(low[T+1..T+d]) >= event_open` —— **无法表达**

已逐层查证：

| 层 | 状态 |
|---|---|
| 数据层（Dataset 五表） | ✅ **原料齐全**：`prefix(rd=0).open` 有，`post(rd≥1).low` 有 |
| 变量层 | ❌ 只有 `holds_event_low_{5,10,20}d`（基准 = 事件日**最低价** `low(T)`）；**没有** `holds_event_open_*`；**没有** d=1..4 的任何版本 |
