## 0. 结论摘要

执行面板现在使用事件级内部身份
`securityId::event:<eventId>`，因此同一证券的每个首板事件都拥有独立的相对日序列，
不再被合并成一条终身序列。公司行为（分红、送转、配股、拆合股）先应用到持仓，
再进入权益计算；连续涨停且 T+1..T+5 没有回踩的样本已在 PIT 条件下排除。

## 4. 关键修正

1. **事件级身份**：面板身份从只有证券改成“证券 + 首板事件”，同一证券后续首板可以再次产生信号和成交。
2. **公司行为**：除权除息不再直接当作价格亏损；分红进入现金，送转和拆合股调整持仓数量。
3. **回踩过滤**：连续涨停或观察期内没有低于首板收盘价的样本不具备回踩资格。
4. **初始资金**：策略文档与留档均为 100,000 元，不再按缺失值或旧默认值展示。
5. **完整明细**：事件级 N5 共 2,348 笔，留档上限提高后页面可以显示全部明细。
6. **末端清算**：事件窗口最后一行没有下一行情时按最后可得收盘价强制平仓；零股允许整仓卖出，避免仓位永久占位、后续年份无法继续交易。
7. **容量收紧**：`v1.3.0` 将两套策略的最大同时持仓统一为 5 只，并分别限制单日新建仓 Top3 2 只、Top5 3 只；执行结果显式记录 `MAX_DAILY_BUYS_REACHED`。
8. **止损 T+1 顺延**：`v1.4.0` 修复「买入日已触及止损但因 T+1 冻结、下一交易日未重新触发」的死区。`002719.SZ@2019-01-21` 现为 2019-01-29 买入、2019-01-30 止损卖出，`holdingPeriod=2`；旧结果延迟到 2019-01-31，`holdingPeriod=3`。

## 5. 复现

```powershell
node_modules\.bin\esbuild.cmd scripts\run3FTopNStrategyBacktest.mts `
  --bundle --platform=node --format=esm --packages=external `
  --outfile=.cache\run3FTopNStrategyBacktest.mjs

node --max-old-space-size=8192 .cache\run3FTopNStrategyBacktest.mjs --topn 3
node --max-old-space-size=8192 .cache\run3FTopNStrategyBacktest.mjs --topn 5
```

运行完成后，结果会写入 `closed_loop_backtest_run`，并在侧边栏「策略 → 策略」的
「3F 综合评分 TopN 闭环回测」卡片中展示。
