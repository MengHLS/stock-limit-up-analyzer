RESEARCH-FINDING-001 B5 — 结论升级 + 引擎接线（Finding→Conclusion→Hypothesis 收口）

## 范围
B4 已落地「六维确定性 Finding 引擎」（结果→发现），但尚未接线到 Run 收口；
且 Conclusion 仍是「只有 DRAFT、不引用 Finding」的旧形态。B5 打通两条链：

  1. Run 完成后自动跑 Finding 检测（失败不杀 Run，落 FAILED 诊断）；
  2. Conclusion 升级为「可引用 Finding、可定稿、可回写假设状态」的收口实体。

## 新增
- `server/researchCore/conclusions.ts`
  - §15 结论状态机：`DRAFT ↔ FINAL`、`SUPERSEDED` 终态（`assertConclusionTransition`）。
  - §15 定稿资格：`FINAL` 必须已引用 ≥1 条 Finding（`assertConclusionFinalizable`，
    「无证据支撑的结论只能停 DRAFT」—— 任务书 §15「Conclusion 不允许凭空产生」）。
  - §26 确定性映射：结论类型 → 假设应回写状态
    （SUPPORTED→SUPPORTED、REJECTED→REJECTED、PARTIALLY_SUPPORTED/INCONCLUSIVE→TESTED）。
  - `assertHypothesisWriteback`（过假设状态机的语义包装）+ `planHypothesisStatusPath`
    （DRAFT→…→SUPPORTED 的**逐级合法链**，BFS；`forward` 图是 `HYPOTHESIS_STATUS_TRANSITIONS`
    的声明子集，测试有漂移守卫）。
- `tests/server/researchCore/conclusions.test.ts`（10 用例：状态机 / 定稿闸门 / §26 映射 / 状态链 / 漂移守卫）。

## 接线（engine.ts）
- `ResearchEngineDeps` 增 `detectFindingsOnRun?`（默认 true）+ `findingPolicy?`。
- `run()` 收口顺序：分析 → `detectFindingsPhase`（`detectAndPersistFindings`，try/catch 落
  `FINDING_DETECTION_FAILED` 但 Run 继续）→ `buildConclusion(findingIds)` → `writebackHypothesisStatus`
  （逐级 `planHypothesisStatusPath`，TESTABLE 前先 `assertHypothesisTestable`）。
- Run 结果新增 `findingCount` / `findingIds` / `findingDetection` / `hypothesisWriteback`。

## 结论仓储守卫（db.ts / inMemory.ts）
- conclusion `update` 过 `assertConclusionTransition`；定稿（FINAL）过 `assertConclusionFinalizable`。
