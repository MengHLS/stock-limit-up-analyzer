# PLAN-C6B4-POSITION-CONTROL-001

## 目标

在 `c6+b4`（高 25% / 中 20% / 低 5% + 最大振幅 < 12%）的基础上，验证除“低分档归零”之外的仓位控制方案：

1. 组合回撤闸门；
2. 单笔风险预算；
3. 总暴露上限；
4. 市场状态过滤；
5. 盈利阶梯锁利。

“低分档归零”已由正在运行的 `c7/c8/c9` 覆盖，本计划不重复造臂。若 `c7/c8/c9` 完成且优于 `c6+b4`，后续叠加实验改用其中最优者作为处理组基准，但固定保留 `c6+b4` 作为参照，避免只与历史结果比较。

## 冻结基线

| 项 | 值 |
| --- | --- |
| 参照组合 | `c6+b4`，`v1.59.6`，留档 #2760001 |
| 数据坐标 | Dataset v5 / `660001` / 2019-01-01 ~ 2026-09-04 |
| 决策 / 成交 | T+5 收盘决策，T+6 开盘成交 |
| 退出链 | 完全冻结为 `v1.44.1` SL-18.1；本计划不改退出逻辑 |
| 当前仓位 | 高 25% / 中 20% / 低 5%，最大 5 仓，单日最多 2 笔 |
| 成本 / 初始资金 | 现有 3F 闭环成本模型 / 100,000 |

### c6+b4 已有事实

留档 #2760001：

 - 累计收益 +46.74%，最大回撤 49.72%，PF 1.1229，夏普 0.3388，卡玛 0.1071；
 - 平均总暴露 69.41%，暴露中位数 70.72%，P90 92.20%，P95 97.44%，最大值 99.93%；
 - 平均持仓数 4.21，暴露超过 80% 的交易日占 38.92%，超过 90% 的占 13.42%；
 - 按建仓年份净盈亏：2019 -0.2k、2020 -19.5k、2021 +20.3k、2022 +2.2k、2023 +5.1k、2024 -3.1k、2025 +42.7k、2026 +24.1k；
 - 2025+2026 贡献约 93.4% 的已完成交易净盈亏；
 - 最大回撤发生在 2019-04-15 ~ 2021-03-10，而同期沪深 300 上涨 25.86%。

最后一条说明：`c6+b4` 的最大回撤不是单纯由指数熊市造成，市场状态过滤不能作为回撤问题的唯一解法；组合回撤闸门、暴露上限和单笔风险预算优先级更高。

### 市场状态诊断

对 #2760001 与沪深 300（`000300.SH`）做只读诊断：

 - 全期 beta 0.4844，下跌日 down beta 0.5934，下跌日捕获 0.475；
 - 指数 <= -2% 的 70 个交易日，策略日均 -1.382%，平均仓位仍为 56.89%；
 - 指数滚动 20 日收益 <= -10% 时，策略 20 日收益均值 -7.49%；
 - T+5 收盘指数趋势分桶：

| 状态 | 完成交易 | 平均收益率 | 净盈亏 |
| --- | ---: | ---: | ---: |
| 指数 <= MA20 且 <= MA60 | 540 | +0.298% | +16,877 |
| 指数 > MA20 且 > MA60 | 462 | +0.024% | +14,401 |
| MA20 < 指数 <= MA60 | 202 | -0.327% | -8,243 |
| MA60 < 指数 <= MA20 | 101 | +1.446% | +20,478 |

趋势状态不是单调关系。简单的“跌破 MA20 就不买”会同时删掉最差桶和最好的反弹桶，首轮不应直接采用。

## 实验原则

1. 每个 arm 只加一个控制维度；先独立跑，再组合最优项。
2. 所有状态使用决策日 T+5 收盘前已知数据，禁止使用未来指数收益、未来权益和未来价格。
3. 闸门只阻止新买，不强制卖出既有持仓；既有止损、止盈、时间退出和候选退出保持原样。
4. 所有减仓都会改变现金路径，禁止用交易层“少亏金额”替代完整账户回测。
5. 仓位参数的收益改善必须同时报告暴露效率，避免用单纯降杠杆冒充选股能力提升。
6. 全窗口最优只用于筛候选；冻结参数后再做 OOS / walk-forward。

## P0：组合回撤闸门（G 组）

### 语义

决策日收盘后：

```text
peakEquity = max(历史每日收盘权益, 当前权益)
currentDrawdown = currentEquity / peakEquity - 1
```

当回撤阈值触发时：

 - 禁止当日所有新买意图；
 - 不卖出现有持仓；
 - 新增跳过原因 `PORTFOLIO_DRAWDOWN_GATE`；
 - 参与后续现金复用判定，但不改写原退出原因。

### 待测规则

| id | 规则 |
| --- | --- |
| g1 | 回撤 <= -10% 起停止新买；回撤恢复到 >= -5% 后恢复 |
| g2 | 回撤 <= -15% 起停止新买；回撤恢复到 >= -7.5% 后恢复 |
| g3 | 回撤带缩放：>-5% 正常；-10%~-5% 乘以 0.75；-15%~-10% 乘以 0.50；<= -15% 停止新买 |
| g4 | 回撤 <= -12% 停止新买，固定冷却 10 个交易日后；若回撤仍 <= -8% 继续停止，否则恢复 |

### 实现触点

 - `server/research/simulator/engine.ts`：维护 `peakEquity`、计算当前回撤，并透传闸门状态；
 - `server/research/simulator/plan.ts`：在进入买入计划前应用闸门或缩放；
 - `server/research/simulator/types.ts`：增加 `portfolioDrawdownGate` 配置快照和 skip code；
 - `scripts/run3FTopNEntryStudy.mts`：登记 g1~g4。

### 重点观察

 - 被闸门拦掉的买入数、空仓天数、恢复滞后天数；
 - 闸门解除后是否错过 2021、2025 的快速反弹；
 - 2019/2020/2024 亏损是否实质收窄；
 - 最大回撤是否降到 40% 以下，而不是只把交易数机械减少。

## P0：总暴露上限（E 组）

### 语义

```text
currentGrossExposure = currentMarketValue / currentEquity
remainingExposure = max(0, maxGrossExposureRatio * currentEquity - currentMarketValue)
```

当日新买目标金额必须满足：

```text
finalBudget = min(
  tierBudget,
  riskBudget,
  remainingExposure * intentWeight / remainingEntriesWeight,
  availableEntryCash
)
```

按 rank 顺序计算，但容量用剩余权重按比例分摊，避免第一个候选吃掉全部剩余空间。暴露上限只限制新买，不改变已有持仓。

### 待测规则

| id | 规则 | 预期约束强度 |
| --- | --- | --- |
| e1 | 总暴露上限 95% | 约 7.35% 交易日会触顶 |
| e2 | 总暴露上限 90% | 约 13.42% 交易日会触顶 |
| e3 | 总暴露上限 85% | 约 23.08% 交易日会触顶 |
| e4 | 总暴露上限 80% | 约 38.92% 交易日会触顶，作为激进诊断臂 |

`c6+b4` 平均暴露已经只有 69.41%，因此首轮主候选是 e1/e2/e3；e4 只有在 e3 显示明确单调收益时才保留。

### 重点观察

 - 触顶天数、平均暴露、P90/P95 暴露；
 - 2020、2024 等亏损年份是否明显降低暴露；
 - 触顶后释放的预算是否仅为延后买入，还是永久丢失强势右尾；
 - 收益下降是否超过暴露下降比例。

## P1：单笔风险预算（R 组）

### 语义

当前项目已有 `RISK_BASED` 枚举，但模拟器明确拒绝执行。本组把它补齐为“单笔最大损失预算上限”，不修改止损价、退出链或单仓股数规则。

```text
stopDistance = 0.06 + 0.002 = 0.062
riskCapFraction = riskPerTrade / stopDistance
finalFraction = min(tierFraction, riskCapFraction, exposureCap)
```

其中 6% 是冻结的止损底线，0.2% 是往返执行成本缓冲，只用决策日收盘价估算目标股数；T+6 开盘成交后报告实际风险距离和跳空穿透率。

### 待测规则

| id | 单笔风险预算 | 6.2% 止损距离对应仓位上限 | 与控制组关系 |
| --- | ---: | ---: | --- |
| r1 | 1.60% | 25.81%（被高分档 25% 封顶） | 实现口径 parity 臂，应逐笔等价于 c6+b4 |
| r2 | 1.30% | 20.97% | 高分从 25% 降到约 21%，中分约 20% 不变 |
| r3 | 1.10% | 17.74% | 高分、中分同时下降 |
| r4 | 0.90% | 14.52% | 防御臂，预计显著降低收益与回撤 |

### 实现触点

 - `server/research/simulator/plan.ts`：实现 `RISK_BASED`，不再抛未实现错误；
 - `server/research/simulator/types.ts`：加入 `riskPerTrade`、`stopDistance`、`riskAnchor`；
 - `server/research/strategySchema/definition.ts`、`legacyViews.ts`、`server/strategyCore/definition.ts`：补齐声明到执行配置的映射；
 - `scripts/run3FTopNEntryStudy.mts`：登记 r1~r4。

### 重点观察

 - r1 必须与 `c6+b4` 逐笔交易、权益曲线逐点一致，否则 risk-budget 适配层不可信；
 - r2/r3 的收益下降是否小于暴露下降；
 - 止损触发交易的实际单笔亏损是否真的靠近预算；
 - 跳空开盘导致实际风险超过预算的比例；
 - 用 `return / averageExposure` 和 `Calmar / averageExposure` 做暴露归一化比较。

## P2：市场状态过滤（M 组）

### 数据前置

市场状态不能复用 Dataset v5 行内的空 `indexClose`。新增独立 sidecar：

```text
.cache/index-daily-000300.SH-2019-2026.jsonl.gz
```

每条记录至少包含：

```text
tradeDate, close, ma20, ma60, return5, return20, drawdownFrom60dHigh
```

由现有 `index_daily` 计算一次并缓存；每个 arm 只读同一 sidecar，不重复查数据库。所有指标只用决策日及之前的指数收盘计算。

### 前置诊断

先对 `c6+b4` 留档运行：

```powershell
node node_modules\tsx\dist\cli.mjs scripts\analyze3FTopNMarketRegime.mts `
  --run-id clrun-3f-top3-v5-v1_59_6-c6-plus-b4-max-amp-12-20260927 `
  --topn 3 --benchmark 000300.SH
```

确认弱市桶的收益、仓位、回撤贡献后，再跑 M 组。

### 待测规则

| id | 规则 | 目的 |
| --- | --- | --- |
| m1 | 指数收盘 < MA20 时停止新买 | 中期趋势闸门 |
| m2 | 指数 5 日收益 < -1% 时停止新买 | 中短期动量闸门 |
| m3 | 指数 5 日收益 < -2% 时停止新买 | 极端弱市闸门 |
| m4 | 指数 < MA20 且 5 日收益 < -1% 时停止新买 | 避免单独趋势条件过严 |
| m5 | 指数 < MA20 时风险乘数 0.5；指数 5 日收益 < -2% 时风险乘数 0 | 连续降仓而非硬切 |
| m6 | 仅跳过 `MA20 < 指数 <= MA60` 的趋势弱桶 | 诊断性臂，检验当前分桶是否稳定 |

### 重点观察

 - 弱市年份 2019/2020/2022/2024 的净亏损是否收窄；
 - 是否误删 `MA60 < 指数 <= MA20` 的强反弹交易；
 - 全期 beta、down capture、2025+ 收益占比；
 - 被过滤候选是否只是被替换成低分候选，而不是真正减少风险。

## P3：盈利阶梯锁利（L 组）

本组改变的是权益曲线风险预算，不应与单笔止损/止盈混为一谈。首轮只做组合级缩仓，不改退出链。

定义：

```text
peakReturn = peakEquity / initialCapital - 1
drawdownFromPeak = currentEquity / peakEquity - 1
```

候选规则：

| id | 规则 |
| --- | --- |
| l1 | peakReturn >= 30% 后风险乘数 0.80；drawdownFromPeak <= -15% 再乘以 0.75，最低 0.40；创新高后恢复到 0.80 |
| l2 | peakReturn >= 30% 后风险乘数 0.80；>= 60% 后 0.60；drawdownFromPeak <= -15% 再乘 0.75 |
| l3 | peakReturn >= 30% 后总暴露上限降到 90%；>= 60% 后降到 75%，只限制新买 |

该组优先级低于 G/E/R：它主要通过降低后期暴露换取卡玛和锁利，若前 30% 收益来自少数右尾，过早锁利会直接削掉主要盈利来源。

## 执行顺序

### 第一批：不依赖新数据的控制臂

1. `c7/c8/c9` 完成后留档低分档归零结果；
2. 在同一批次重跑 `c6+b4` 并完成逐笔一致性门禁；
3. 跑 `e1/e2/e3`；
4. 跑 `g1/g2/g3`；
5. 跑 `r1` 做 parity，通过后再跑 `r2/r3/r4`。

### 第二批：组合筛选

1. 在 E/G/R 中每个维度只保留最优 1 个；
2. 测试 `低分归零最优 + E 最优`；
3. 再叠加 `G 最优`；
4. 再叠加 `R 最优`；
5. 最多保留 2 个组合进入 OOS，不做全笛卡尔积。

### 第三批：市场和锁利

1. 构建指数 sidecar 并跑 M 组；
2. M 组只有在前两批仍不能改善 2019/2020/2024 时，才进入组合；
3. L 组最后跑，且只叠加在已通过第一批的组合上。

## 共同验收门槛

### 技术门禁

 - parity arm `r1` 与 `c6+b4` 的完成交易数、期末权益、逐笔记录、权益曲线一致；
 - `c7/c8/c9` 与后续叠加臂均使用同一 Dataset v5、同一退出链、同一成本模型；
 - 现金永不为负；被闸门/暴露上限拒绝的意图必须写入 `skipped`，不能静默丢弃；
 - 所有指数特征通过 leakage guard，缺失指数数据时不得伪造。

### 风险与收益门禁

首轮筛选建议采用以下暂定门槛：

1. 累计收益 >= `c6+b4 - 3pp`，即 >= +43.74%；
2. 最大回撤 <= 45%，较 `c6+b4` 至少改善 4.72pp；
3. PF >= 1.08，夏普 >= 0.30；
4. `return / averageExposure` 不低于 `c6+b4`，避免只靠降杠杆；
5. 至少 5/8 年份为正，且 2025+2026 净盈亏占比从 93.4% 降到 <= 85%；
6. 被拒绝/未成交/`openAtEnd` 结构不得异常恶化。

最终晋级标准：

 - 在独立 OOS 窗口中保持方向一致；
 - 参数邻域内结论不翻转；
 - 与 `c6+b4` 相比，至少同时改善两个核心指标（最大回撤、卡玛、PF、夏普），且累计收益不下降超过 3pp；
 - 报告中必须单列 2019/2020/2024 弱年贡献和 2025+ 收益集中度。

## 推荐优先级

| 优先级 | 方向 | 原因 |
| --- | --- | --- |
| P0 | 总暴露上限 e2/e3 | 平均暴露 69.4% 但 P90 92.2%，上限能直接控制尾部暴露 |
| P0 | 回撤闸门 g1/g2 | 直接针对 49.72% 回撤和 2019-2021 慢回撤；但需防止错过反弹 |
| P1 | 单笔风险预算 r2/r3 | 把仓位从“按分数固定比例”变成“按止损风险预算”，理论最清晰 |
| P2 | 市场状态 m4/m5 | beta 仅 0.48，硬过滤可能删掉反弹；先诊断再决定是否组合 |
| P3 | 盈利阶梯锁利 l1/l2 | 更可能提高卡玛但压低收益，应在核心组合确定后再测 |

## 运行方式

当前 runner 已支持数据缓存和多 arm 单进程复用。新增 arm 后统一使用：

```powershell
node --max-old-space-size=8192 node_modules\tsx\dist\cli.mjs `
  scripts\run3FTopNEntryStudy.mts --arms control,c6b4,e1,e2,e3,g1,g2,g3,r1,r2,r3
```
