## RESEARCH-004：分段窗变量族 + 两窗关系分析（用户诉求「T→T+5 最大回撤 与 T+5→更远 的关系」）

### 诊断坐标（为什么原系统做不到）

### A. 分段结果变量族（`server/researchEngine/variables.ts` + 新增 `segmentWindows.ts`）
- 命名 `segment_{stat}_{a}_{b}d`：**锚点 `close(a)`**，**取值窗 `[a+1, b]`（不含锚点日）**。四种口径：`return` / `max_return` / `max_drawdown` / `min_return`。
- 🔴 **`a=0` 时不新造，复用既有族**（`future_return_{to}d` / `{stat}_{to}d`）—— 否则同一语义两条路径。
- 🔴 **不进 `listOutcomes()`**（否则目录从 95 膨胀到 760 个名字，前端下拉不可用）；但 `hasOutcome` / `resolveOutcome` **必须认得**（按需构造）。
- 取值口径与既有族**逐字节同源**（同一 `path` 物理层、同一统计实现），只是换锚点。

### B. 两窗关系分析类型 `SEGMENT_RELATION`（新增 `server/researchEngine/analyses/segmentRelation.ts`）
- 语义：窗 A `[a+1,b]` 的表现 **vs** 窗 B `[c+1,d]` 的表现；产出分档对比 + 配对指标 + 顶底档差 + 方向一致性。
- 🔴 **重叠守卫 `WINDOW_OVERLAP`**：`[a+1,b] ∩ [c+1,d] ≠ ∅` 即拒绝 —— 与 `INVALID_ANALYSIS_CONFIG` **分开**（映射 tRPC `BAD_REQUEST`），因为这是「研究设计错误」不是「参数写错」。**紧邻窗（b+1=c）不算重叠**。
- 🔴 **不产 `WIN_RATE`** 当窗 B 口径是 `max_drawdown`：理由改过一次 —— **不是**「恒为非正」（❌ 错，取值窗不含锚点日，价格整段上行时窗内最低收盘仍可高于锚点收盘），而是**「取值 > 0 的占比」根本不是通常意义上的胜率**，列出来只会诱导误读。

### C. 配对指标层（`metrics.ts` 新增 `computePaired()` / `alignedPairs` / `listPairedMetricCodes`）

**🔴 三处会读反的地方**：
1. **档号不含方向**：`cutPoints = [−9.11%, −5.03%, −1.95%, +2.01%]` ⇒ **档 1 = 跌最深、档 5 = 跌最浅（甚至还涨着）**，而结论只写「第 5 档 − 第 1 档 = −1.8%」。读者默认会把「第 5 档」当成跌最狠那批 ⇒ **符号恰好读反**。
2. **`SPREAD_TOP_BOTTOM` 的 top/bottom 是「分组变量值」的首尾，不是「跌得深浅」**：对「跌幅」这种越负越严重的变量，`top − bottom` 天然为负，与「越深越强吗」的直觉正面打架。**真实答案是「越深之后反而略强」**。
