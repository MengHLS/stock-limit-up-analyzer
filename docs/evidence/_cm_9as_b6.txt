RESEARCH-FINDING-001 B6 — tRPC 端点（Finding / Hypothesis 补充 / Candidate 从假设转出）

## 范围
B5 已在引擎层打通 Finding→Conclusion→Hypothesis 收口，但对外**没有一条 API**。
B6 把发现层与假设转正暴露为稳定 tRPC 端点，且每条写路径都过领域守卫。

## 新增端点（researchEngineRouter）
### Finding
- `listFindings`（GET）：按 experimentId / runId / findingType / status / minResearchStrength 过滤。
- `getFinding`（GET）：单条明细（NOT_FOUND 兜底）。
- `detectFindings`（POST，admin）：对某 Run 重跑 Finding 检测（`FindingEngine.detect`），
  只读 `research_result`（§28），重跑幂等（fingerprint 去重）；失败走 `toTrpcError`。
- `reviewFinding`（POST，admin）：用户 review 状态流转，过 `assertFindingTransition`
  （DISCOVERED→REVIEWED→SUPPORTED 逐级，跳级 BAD_REQUEST）。

### Hypothesis 补充（create/update/delete 已存在）
- `getHypothesis`（GET）：单条明细。
- `testHypothesis`（POST，admin）：置 TESTABLE 时过 `assertHypothesisTestable`（三件套），
  其余过 `assertHypothesisTransition`（状态机，禁止跳级）。
- **`createHypothesis` / `updateHypothesis` 扩字段**：补 `researchQuestion` / `conditions` /
  `target` / `horizon` / `expectedDirection` / `expectedEffect` / `sourceFindingIds` /
  `sourceConclusionId` —— 原 schema 只收 name/statement，假设无法经 API「形式化」，
  等于 §26 链条在入参层就断了。

### Candidate
- `createCandidateFromHypothesis`（POST，admin）：仅 `SUPPORTED`/`PROMOTED` 假设可转
  （`assertHypothesisReadyForCandidate`，§26「不要自动生成 Strategy」）；
  产物 DRAFT 候选 + 继承条件 + 落 `sourceHypothesisId` / `sourceFindingIds` / `sourceDatasetVersionId`
  / `sourceResearchRunId` 谱系锚；**不**自动转正 Strategy。

## 关键实现点
- 新增 `conditionSetSchema`（`{groups:[...]}` 已序列化形态），`value: z.unknown()` 后经
  `as ResearchConditionSet` 收敛；取值合法性由 `assertConditionSet`（Repository 层）把关。
- 运算符沿用**符号形**闭集（`>` / `>=` …，`RESEARCH_CONDITION_OPERATORS`），
  与草图侧一致（名称形只在 `definitionBuild#CONDITION_OPERATOR_MAP` 翻译）。
