# RESEARCH-007.2 — Research 结果「矩阵视图」（把批量分析拼回一张表）

> 触发：用户实报「这个结果每一个分析都是单独的，100 多个分析结果根本没法看，而且并没有生成你上个回答里面的那样的 5×5 表格。那样的表格可能更有助于我分析结果，有什么办法可以在前端页面上加上那样的表格，从而更容易的判断是否有效」。
>
> 定位：**纯前端能力补全**。`server/**` 一行未改、零迁移、零新端点、零新依赖。
>
> 交付日：2026-09-13 00:35 GMT+8

## 1. 问题（先复现，再动手）

Run `540001` 有 **135 个 CONDITIONAL 分析**（A 组 5 + B 组 125 + C 组 5），但「结果」页签的实现是：

```
[ #480001 CONDITIONAL ] [ #480002 CONDITIONAL ] … ×135 个按钮
        ↓ 点其中一个
      单个分析的「结论速览 / 分组对比图 / 分组结果表 / 整体指标」
```

即：**一次只看得到一格**。而这一批分析的信息本身就是「决策日 × 回撤桶」的二维表 ——
「T+2 的 4~6% 桶 vs T+4 的 4~6% 桶」这种横比在页面上**做不了**，用户只能把 135 个数字抄下来自己拼表。

这是**展示层的结构性缺失**，不是数据缺失，也不是引擎缺陷。

## 2. 方案选择

| 方案 | 代价 | 结论 |
|---|---|---|
| A. 加后端聚合端点 `getRunResultMatrix` | 改 `server/**` ⇒ **热重启会杀死在途研究 Run**（项目铁律）；且要新增「矩阵」这一领域概念 | ❌ 否决 |
| B. 把矩阵**导出成文件**（离线脚本生成 markdown/CSV） | 零风险，但用户每次看结果都要重跑脚本；页面上依然看不出 | ❌ 不解决诉求 |
| **C. 纯前端聚合：解析分析元数据 → 惰性拉结果 → 拼表** | 只动 `client/**`；首屏只拉当前选中族的 25 个分析 | ✅ **采用** |

选 C 的依据：**页面已经拿到了矩阵的全部原料**。

- `researchEngine.getRun({ runId })` 已返回该 Run **全部分析**的 `name` / `target` / `status`；
- `researchEngine.getAnalysisResults({ analysisId })` 每个格子已有结果，且结果行里**自带**
  `dimension.group = ALL / CONDITION`、`DIFFERENCE`、`T_STAT_DIFFERENCE`、`P_VALUE_DIFFERENCE`
  （`server/researchEngine/analyses/conditional.ts` 的落库结构）。

所以「横比」不需要新数据，只需要一个**把散落的格子拼回去**的展示层。这正是前端该做的事。

## 4. 归组契约（本视图唯一有实质判断的地方）

后端**不返回条件行**（条件在单独的表里，逐分析取会再多 135 次请求），所以坐标从下面两处解析：

| 维度 | 来源 | 是否权威 | 规则 |
|---|---|---|---|
| 指标族 | `target`（结构化） | ✅ 权威 | `segment_(return\|max_return\|max_drawdown)_(\d+)_(\d+)d` ⇒ `familyKey = {kind}_{end−start}`，中文名由**变量语义**推导（`return_5` → 「之后 5 日收益」） |
| 决策日 | `name` 的 `T+d` | 与 `target` **交叉校验** | 两者必须一致，不一致 ⇒ 进 `unclassified` 并写明「名称决策日 T+1 与 target 的起始日 T+2 不一致」 |
| 回撤桶 | `name` 的 `回撤X~Y%` | ⚠️ 只能来自文本 | 固定桶 `0~2% / 2~4% / 4~6% / 6~8% / 8%+`；无桶但写「已回撤」⇒ 归到参照列「已回撤(不限幅度)」 |
| 口径 | `name` 含「未破」 | ⚠️ 只能来自文本 | 独立成一个 scope（`EVENT_LOW_GUARD`），**不与无资格约束的格子混在同一张表** |

### 已知边界（写进 UI，不藏）

> 归组依赖**分析名**。给分析改名会让它脱离矩阵 —— 此时它**不会消失**，而是出现在「未归类」里，
> 带一行具体原因（如「条件段里没有 `T+d` 形式的决策日」），并且可以从那里点进去。

这是刻意选择的诚实边界：与其硬猜坐标，不如把猜不出来的东西**如实列出来**。

## 5. 口径纪律（防「把错误口径读成结论」）

### 5.1 排除「口径不一致」的结果行

`CONDITIONAL` 分析**会自动附送一行 `MAX_DRAWDOWN`**，其 `variable` 由 `drawdownVariableFor(target)`
从 target 名尾部推导（`segment_return_2_7d` → `max_drawdown_7d`），**与 target 不是同一个变量**
（§44.5 第 9w 条 / 记忆里的既有坑）。

矩阵在提取时做**两道自证**：

1. `details.outcomeVariable` 必须等于 `target`；
2. `details.variable` **若存在**必须等于 `target`。

不满足的行被**排除并计数**（`excludedRowCount`，鼠标悬停可见「已忽略 N 行口径不一致的指标行」）。
真实数据里每格命中 **1 行**（就是那行 `MAX_DRAWDOWN`）—— 已实测确认。

### 5.2 显著性 = 与「全样本」比，不是与相邻桶比

格子里 `*` / `**` 来自引擎落库的 `P_VALUE_DIFFERENCE`（Welch 两样本），**比较对象是全样本**
（全部首板事件，含未回撤的）。UI 原文写明：

> 「显著为负」= 比全部首板事件表现差，**不是**比隔壁那一格差。

且沿用引擎原文的免责：**未校正多重比较、窗口互相重叠** ⇒ 25 格逐个检验时纯靠运气也会出现若干「显著」，
**本视图给的是线索，不是结论**。

### 5.3 小样本不判显著

引擎写进 `details.lowSample` 的格子一律不标 `*`，改标「小样本」并说明「小样本下 p 值不可靠」。

### 5.4 不产生新统计量

- 格子主值 / 中位数 / 胜率 / 标准差 / 差值 / t / p **全部取自落库结果**，前端不重算；
- 行小结只给**格数 / 样本数合计 / 显著格数**（加法与计数）。
  **不做按样本数加权平均** —— 各格样本是否互斥、并集是否等于全集取决于建批方式，前端无从校验，宁可不算。

## 6. 界面行为

- **默认进入矩阵视图**（不再默认逐分析）。
- **指标族切换**：`之后 1 日收益 / 之后 3 日收益 / 之后 5 日收益 / 之后 5 日最大有利偏移 / 之后 5 日最深跌幅`，
  每个按钮上带该族的分析数。
- **口径切换**：当存在带资格约束的分析时，出现「无资格约束 / 加『未破首板日最低价』资格」两个口径。
- **惰性取数**：只对当前选中的（口径 × 族）发请求（≤30 个分析），由 tRPC 批链接合并；切族时**不**预取其他 100 个分析。
- **表格**：
  - 行 = `T+1 … T+n`（n 取该族最大决策日；缺的天如实显示为「未建」行）；
  - 列 = 参照列「已回撤(不限幅度)」+ 固定桶（按 `0~2% → 8%+` 固定顺序，跨 Run 可比）；
  - 每格 = 主指标值（红=高于全样本、绿=低于全样本）+ 显著性标记 + `n=`；
  - 悬停显示：分析名 / 条件组均值与 n / 全样本均值与 n / 差值 / 差值口径 / **引擎原样的 `conditionRule`** / 中位·胜率·标准差；
  - 「未建」（无该分析）与「无结果」（有分析但结果不可用）**分开显示**；
  - 点任一格 → 切到「逐分析」并选中该分析。
- **未归类**折叠区：列出所有解析不出坐标的分析 + 原因 + 可点击跳转。

## 9. 已知边界（不做的事）

1. **不改后端**：矩阵是展示层聚合，不是新的领域对象。若将来要把「矩阵」做成可保存的实体（如 Analysis Group），
   那属于新的领域设计，不在本任务。
2. **不硬编码研究结论**：组件里没有任何阈值、桶定义之外的业务判断；桶顺序与显著性阈值是**展示常量**并已集中声明。
3. **不替代逐分析视图**：矩阵回答「哪一格值得看」，逐分析回答「这一格到底筛了什么」。
4. **未归类不隐藏**：改名 / 非该模板的分析一律列出 + 原因。
5. **不做格间两两检验**：现有落库结果只有「条件组 vs 全样本」的检验，没有桶与桶之间的检验；
   硬造一个「相邻桶差」在前端会变成**不可验证的新统计量**，不做。
