## 4. 修复真实排序与诊断一致性

### 4.1 最小实现

在 R 的**每日候选选择入口**消费 `sortCandidates(cells)` 的返回值，然后取 Top3。建议把排序局限在 R 选择回调/最小选择函数；不要为了修 R 重排 Random 的输入列表，造成同种子抽样发生额外变化。

明确保留顺序：确认日价格信号 → 当日 ST 参与资格 → 身份可解析 → R排序或Random抽样 → 计划 → 撮合容量/现金/涨跌停/成交前资格检查。

不要预先用次日状态排除前日候选；也不要按现金/持仓先删股票来补入第4名。Top3入选不意味着三只都能成交，每日最多2买入仍由原执行层裁决。

### 4.2 同一选择结果产生计划和诊断

排名产物应消费实际候选宇宙与实际计划选择，不能另造一个排序结果再猜 `selectedByR`。至少可核实：

- 确认日期、group、anchorEventId、symbol、preReturn10。
- 当日是否可参与、排除原因、参与候选数、实际因子名次/破平键。
- 是否进入 R 计划、真实计划顺序。
- 成交/未成交的对应日期、原因或证据引用。

已知ST或身份不可解析的候选可以保留在原始信号账，但应明确其未参与排序、未入选；参与名次不要混同原始价格候选名次。

输出新结果时，旧报告、旧Run和旧产物保持不变。生成新实验codeDigest；实验计算版本如需递增，按现有规则处理并说明，不能只改展示标签。旧StrategyVersion不变。

### 4.3 必须锁定的回归

新增有意义的接线测试，不能只测试排序函数返回值：

1. 同日≥5个信号，代码顺序和因子顺序冲突：R计划必须选出因子前三名，低代码低因子不能挤入。
2. 比较两个相反的候选输入顺序：R计划结果相同；相同因子值按原 symbol/eventId 破平规则确定。
3. 排除确认日已知ST后，对剩余候选正确排序；UNKNOWN按显式政策可参与，默认严格模式仍拒绝。
4. 候选排名、`selectedByR`、计划集合逐项相等；针对≥4候选走真实实验计划/直接下游，而非测试里自行实现另一套排序。
5. 使用真实撮合的最小夹具：所成交 R 股票都来自对应确认日的实际Top3；容量跳过不递补第4名。
6. 验证真实成交前转ST被拒、当日权益仓位随盈亏变化、再入场不新增永久禁止，复用已有相关测试即可。
7. 同候选池、同种子时 Random抽样/业务结果不因 R排序修复改变；若意外变化，先查输入顺序和共享状态，不能静默接受。

排序修复后 R 的交易/权益指纹**预期会变**，不要以旧R收益或旧R指纹不变为验收条件。Dataset、原始信号集合、资格政策、冻结参数及独立Random结果应保持可比。
