## 目标

在 `v1.44.1`（SL-18.1，峰值回撤 8% 止损）冻结出链的基础上，系统性验证四类建仓策略：

1. 市场状态/弱市过滤；
2. 绝对风险过滤（观察窗振幅、破位深度）；
3. 分层仓位（按 3F 评分/排名分配仓位）；
4. 分批买入（拆成两笔建仓 + 可选确认条件）。

原则：

- 只新增实验版本，不回写、不覆盖既有版本；
- 交易层子样本结论只用于选参数，不作为最终依据；每个变体必须跑完整账户闭环；
- 所有数据坐标保持 Dataset v5、2019-01-01 ~ 2026-09-04、当前成本模型；
- 全窗口筛选后必须再做 OOS / walk-forward，禁止把全窗口最优直接当可用策略。

## 对照实验设计

本轮所有实验采用“`v1.44.1` 对照 + 单维度处理”的 A/B 设计：

1. **对照组 = `v1.44.1`，且必须作为同一批次的一个真实回测 arm 落库**。
   - 优先复用历史留档 #2130001 的坐标与口径；
   - 但如果当前代码/数据与 2026-09-27 留档可能不同步，先做一个 fresh
     `clrun-3f-top3-v5-v1_44_1-control-<YYYYMMDD>` 重跑，不能直接假定旧留档仍是有效对照。
2. **对照重跑先过逐笔一致性门禁**：
   - 完成交易数、期末权益、权益曲线点数与 #2130001 一致；
   - 成交逐笔（securityId + 入场/出场 + 数量 + 净盈亏 + 退出原因）差异 = 0；
   - 不一致 ⇒ 冻结新代码/新数据坐标，本次不使用旧留档作为对照。
3. **每个处理 arm 只改一个建仓维度**，其余（退出链、成本、仓位上限、数据、窗口）与对照完全相同；
4. **验收比较一律写成 `处理组 − 对照组`**，不用绝对阈值代替差分；
5. 控制组的 runId 统一带 `-control`，实验结论表第一行固定为对照行。

## 共同验收门槛

每个变体与 **同一批次落库的 `v1.44.1` 对照组**对比以下指标，全部来自闭环留档：

- 累计收益、年化、最大回撤、夏普、索提诺、卡玛、胜率、PF、完成交易；
- 年度净盈亏（按成交年份）与权益曲线年度变化；
- 拒单/未成交/`openAtEnd` 数量不得异常增加；
- 参数变化不得改变排序键口径、不得引入前视。

暂定通过门槛（可先作为基线，不替代 OOS 判定）：

1. 累计收益相对对照的差分 ≥ 0，且对照重跑通过逐笔一致性门禁；
2. 最大回撤相对对照不劣于 1.3pp（即对照 51.68% → 上限 53%）；
3. PF 相对对照不下降超过 0.04，且不低于 `1.05`；
4. 年度正向年份数 ≥ 5/8，且收益不能只靠 2025+2026 两年；
5. 全窗口入选后，再做至少一个独立样本外切片（建议 2022-2024 或 2024-2026）。

## A. 市场状态/弱市过滤

### 依据

`v1.44.1` 年度净盈亏集中在 2025 `+33,224.28`、2026 `+20,660.39`；2019/2020/2022/2024 均为负。弱市年份的建仓大概率系统性负期望，因此先做“弱市不建仓/降仓”测试。

### 前置诊断

1. 对对照组跑 `scripts/analyze3FTopNMarketRegime.mts --run-id clrun-3f-top3-v5-v1_44_1-peak-drawdown-8-20260927`：
   - 全期 beta、up/down capture；
   - 指数下跌日策略是否跌得更多；
   - 最大回撤期间仓位是否仍近满仓。
2. 输出年度/季度指数状态 × 策略收益对照表，确定“弱市”的候选定义。
3. 只读统计不写 DB；诊断结论进 `docs/evidence/`。

- 弱市年份（2019/2020/2022/2024）净亏损明显收窄；

## B. 绝对风险过滤

### 依据

12F 因子研究已有风险桶证据：观察窗平均振幅 `>=8%` 为 NEGATIVE；深破位（回撤深度过深）为风险方向。3F 合成分虽然把低振幅排得更高，但弱市里 Top3 仍可能全部是高波动候选，因此需要绝对阈值而不是换排名键。

### 前置诊断

1. 用 `scripts/analyze3FTopNObservationDropStats.mts --run-id <v1.44.1 runId>` 统计实际成交中：
   - 观察窗是否出现单日跌 `>=5%`；
   - 最大收盘跌幅、平均振幅分桶；
   - 此后 T+6..T+20 收益分层。
2. 用 `docs/evidence/_analysis_3f_topn_score_stats_1_44_1.json` 复核：加入硬门槛后是否误杀高分/强势续持右尾。
3. 子样本分层只用于定阈值和猜方向，不上结论；结论以完整闭环为准。

### 待验证的绝对风险特征

全部按 T+5 决策日收盘可算，PIT 安全：

| 特征 | 口径 | 候选阈值 |
| --- | --- | --- |
| `observationMeanAmplitude` | T+1..T+5 平均振幅 = mean((high-low)/preClose) | `< 8%` / `< 7%` / `< 6%` |
| `observationMaxAmplitude` | T+1..T+5 最大振幅 | `< 12%` / `< 10%` |
| `drawdownFromEventClose` | 观察窗最低价相对首板收盘的破位深度 | `> -10%` / `> -8%` / `> -6%` |

## C. 分层仓位

### 依据

v1.44.1 的评分分层显示：

- `score >= 0.7167` 只保留 265/1362 笔，净盈亏 50,803.91 → 19,716.74；
- 硬门槛会砍掉中分段强势续持大赢家；
- 高分段的平均收益更好，但总净盈亏依赖中分段右尾。

因此不硬切，而是“高分满仓、中分半仓/小仓”，保留右尾参与权。

### 待测规则

| 编号 | 规则 |
| --- | --- |
| T1 | `score >= 0.7167` → 20%；`0.55 <= score < 0.7167` → 10% |
| T2 | `score >= 0.7167` → 20%；`score < 0.7167` → 5% |
| T3 | `score >= 0.65` → 20%；`score < 0.65` → 10% |
| T4 | rank 1 → 20%；rank 2 → 15%；rank 3+ → 10% |

### 测试矩阵

| 版本 | 方案 |
| --- | --- |
| `1.44.1-control` | 对照组（同上，先过逐笔门禁） |

### 前置能力改造

### 通过条件

- 全账户收益 ≥ 对照组，回撤不劣于对照组 1.3pp 上限；
- 现金充足率/拒单原因没有系统性恶化。

## D. 分批买入

### 依据

当前一次性 T+6 开盘买满，单次开盘跳空/选错事件的风险被完整承担。拆成两笔后：

- 第一笔保留 T+6 开盘信号；
- 第二笔由确认条件决定是否执行，降低“买在坏开盘”的全仓损失；
- 代价是仓位到位慢、可能出现半仓未确认，必须用完整账户验证机会成本。

### 待测规则

| 编号 | 规则 |
| --- | --- |
| S1 | T+6 开盘 50% + T+7 开盘 50%（无条件） |
| S2 | T+6 开盘 50%；T+6 收盘 ≥ 建仓成本才在 T+7 开盘买 50% |
| S3 | T+6 开盘 50%；T+6 收盘 > MA5 才在 T+7 开盘买 50% |
| S4 | T+6 开盘 70% + 确认后 30%（前重） |
| S5 | T+6 开盘 30% + 确认后 70%（后重） |

### 测试矩阵

| `1.44.1-control` | 对照组（同上，先过逐笔门禁） |

### 前置能力改造

- 扩展执行模型（如 `NEXT_OPEN_SPLIT`）与订单计划：
  - 第一笔固定 T+6 开盘；
  - 第二笔按确认条件生成/取消；
- 模拟器需要支持：同一信号两笔订单、T+1 冻结/现金占用、整手、单日最多建仓 2 笔的语义（两笔是否会占用同一日的 2 个名额需要明确定义）；
- `server/research/patternLibrary/threeFactorTopNStrategy.ts` 暴露 `entrySplits` 参数。

### 通过条件

- 两笔成交的切片加权净收益 vs 对照组一次性买入可比；
- 第二笔确认失败导致半仓时，机会成本显式报告；
- 完成交易数/持有期口径在报告里单独说明，不能和一次性买入直接比成交笔数。

## 执行顺序

0. **先跑 `v1.44.1-control` 对照组**（同一批次、同一代码快照），逐笔门禁通过后，再开处理 arm。
1. **B 绝对风险过滤**优先：改造最小，因子证据最直接，先跑 `1.58.x`。
2. **A 市场状态过滤**第二：需要指数特征前置，跑 `1.57.x`。
3. **C 分层仓位**第三：需要仓位引擎改造，跑 `1.59.x`。
4. **D 分批买入**最后：执行模型改动最大，跑 `1.60.x`。
5. 如 A/B 有组合效果，先做 `A 最优 + B 最优`，再在其上叠加 C/D。

每轮最多两个回测进程并行，结果统一写入 `closed_loop_backtest_run`。

## 风险与红线

- 任何子样本分层结论都必须经过完整回测复核；
- 新增特征必须在决策日 PIT 可算，通过 leakage guard；
- 过滤/减仓会释放现金，可能改变后续买入和权益路径，不能外推“少亏了多少”；
- 全窗口最优存在多重检验风险，只做“候选”，转正必须走 OOS/walk-forward；
- 本轮只研究建仓侧，v1.44.1 的退出链保持不变。
